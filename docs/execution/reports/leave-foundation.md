# 연차 지급·만료 기반 — 2026-10-26

200_leave_foundation.sql을 실제 Supabase SQL Editor에서 적용했다. CLI migration history는 등록하지 않았으므로 중복 실행하지 않는다.

- leave_grants: 건당 1개, UID+획득 주 UNIQUE. 최초 지급 없음. 월요일 06:00 주간, 6번째 양수 목표 달성 시 획득, 진행 중 포함. 만료는 획득 주 시작+21일 06:00이고 정각부터 제외한다.
- 각 공부 날짜의 당시 목표 버전과 날짜별 세션 정수 초를 사용한다. 세션별 내림을 기존 _day_record와 동일하게 적용하고 누적 목표를 처음 넘는 시각을 계산한다. 주간 6번째 시각을 earnedAt으로 보존한다.
- get_leave_status는 본인 프로필을 잠근 뒤 시각을 잡고 과거부터 누락된 획득분을 보충한다. 유일 제약과 잠금으로 재시도/동시 지급 중복을 막는다. 지급 행이 생기는 시각(recorded_at)과 획득 시각(earned_at)은 다를 수 있다.
- RLS: 본인 지급 SELECT만 허용한다. 비회원 조회/RPC, 타인 조회, 클라이언트 쓰기 및 내부 계산 함수 호출은 차단한다. API에 사용자·시각·지급량 인자를 받지 않는다.
- 실제 SQL 롤백 테스트 통과: 6번째 진행 중 목표 도달 직전/정각, 7일 달성과 반복 조회 중복 방지, 과거 지급의 실제 시각/고정 만료, 미만료 잔액 집계, 휴무/미설정 제외, 주간 경계를 걸친 연속 6일 제외, 06:00 분할·여러 세션 누적, 본인/타인 RLS, 인증/비회원 권한. 기존 테스트 계정만 사용했고 생성한 세션·목표·연차는 롤백했다. 진짜 동시 연결 경합·만료 순간의 실시간 UI는 미검증이다.
- 자동 테스트 전체 29개, 타입 검사, 린트 통과. UI와 사용·취소·차감·출석 대체는 미구현이다. 다음 구현에서 이 부분을 완료로 오인하지 않는다.
- 스케줄러 없이 조회 시 기록한다. 향후 화면은 진입·복귀·목표 달성 시 getLeaveStatus를 호출해야 한다. 앱을 열지 않아도 자격/만료 계산은 보존하지만 백그라운드 지급 알림은 없다.
