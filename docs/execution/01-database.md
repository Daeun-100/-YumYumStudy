# 01 — DB·데이터 연결 (병렬 A)

선행: 00 병합. 소유: `supabase/**`, `src/data/**`, DB 통합 테스트. 화면·공통 타입·패키지 파일은 수정하지 않는다.

## 작업

1. `100_*` 마이그레이션으로 고정 방 1개, UID 기반 프로필, 세션, 목표 버전/스냅샷에 필요한 최소 스키마를 작성한다. 현재 불필요한 연차 테이블·범용 그룹 체계를 만들지 않는다.
2. 프로필 초기화는 인증 UID로 멱등 생성하고 고정 방에 자동 배정한다. `src/data/profile.ts`의 ensureProfile을 연결한다. 기본 표시 이름은 UID에서 만든 `공부친구-짧은ID`로 하되 소유권은 전체 UID로 판정한다. 이름 편집 UI는 이 작업에 포함하지 않는다.
3. 시작 RPC는 사용자별 진행 중 세션 한 개를 DB 제약으로 보장하고 requestId 재전송을 처리한다. 종료 RPC는 세션 소유권을 검사하고 서버 종료 시각을 한 번만 저장한다. DB 직접 쓰기로 시각·소유권을 우회하지 못하게 한다.
4. getToday/getRoom/getHistory는 종료 세션과 진행 세션을 분리하고 오전 6시 경계로 나눈다. 진행 중 세션의 과거 날짜 부분도 기록 조회 시 현재 기준 잠정 시간으로 다룰 필요가 있다면 계약 변경 요청을 남기며 종료된 시간으로 위장하지 않는다.
5. getGoals는 미설정 null을 반환한다. saveGoals는 정책 미정 동안 POLICY_PENDING을 반환한다. 목표 확정 전 가짜 기본 목표나 출석을 생성하지 않는다.
6. 필요한 세션 테이블을 Realtime publication에 등록하고 subscribeStudyChanges를 연결한다. RLS로 허용된 고정 방 데이터만 조회한다. 최초 구독·재연결 레이스 처리는 화면 계약에 맞춰 상태를 전달한다.
7. 함수별 SQL 이름·매개변수·오류 변환을 `src/data/study.ts` 안에서만 처리한다. 클라이언트 UID 입력으로 타인 소유권을 선택하지 않는다.

## 검증

- 익명 인증된 UID A/B는 방 현황을 볼 수 있다. 인증 없는 요청은 거부된다.
- A가 B의 세션 종료·목표 변경·프로필 위조를 할 수 없다. RPC 권한과 search_path도 확인한다.
- 동시 시작 2건, 같은 requestId 재전송, 종료 응답 유실 후 재시도에서도 세션·시간이 중복되지 않는다.
- 6시 경계와 여러 날 세션 합산을 00의 계산 예제와 비교한다.
- 마이그레이션을 새 로컬 DB에 적용한다. DB 실행 환경이 없다면 SQL 작성 완료와 실행 검증 대기를 분명하게 구분한다.
