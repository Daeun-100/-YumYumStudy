# 02 — 내 타이머 (병렬 B)

선행: 00 병합. 소유: TodayScreen, useTimer, index 라우트, tests/timer. 실제 DB 연동 검증은 01 완료 후 가능하다.

## 화면

- 공부 날짜, 오늘 확정 누적, 진행 세션 시간, 오늘 총시간을 구분해 표시한다.
- 시작/중지 버튼과 요청 중·저장 실패·재시도 상태를 제공한다. 요청 중 반복 탭을 막는다.
- 목표 미설정이면 미설정으로 표시하고 0분 달성으로 취급하지 않는다.
- 다른 앱 사용·잠금 중에도 시간이 포함됨을 짧게 설명한다.

## 동작

1. 프로필 초기화 완료 후 getToday를 호출한다. 서버 시각으로 화면 시계 기준을 잡는다.
2. 시작·실패 재시도는 인자 없이 startStudy()를 호출한다. 요청번호 생성·UID별 영속 저장·같은 번호 재전송은 구현된 코어가 담당한다. 앱 초기화 시 IdentityProvider가 미완료 요청을 복구한다. 화면에서는 직접 UUID나 시작 RPC를 만들지 않는다. 서버 승인 전 성공 화면을 표시하지 않는다. 복구 후 getToday로 최신 상태를 조회한다.
3. 중지 실패 시 세션을 임의 종료하지 않는다. 응답이 유실된 경우 재조회로 종료 여부를 확인한다. 새 시작은 종료 상태 확인 후 허용한다.
4. 화면 이탈·잠금·unmount 시 중지 요청을 보내지 않는다. 로컬 interval은 화면 표시용으로만 사용하고 cleanup한다.
5. 화면 복귀·구독 재연결·변경 알림 시 재조회한다. 중복 조회 응답이 최신 상태를 덮어쓰지 않게 한다.
6. 6시를 지나면 공부 날짜와 오늘 합계를 갱신한다. 진행 세션 전체를 새 날짜에 더하지 않는다.

## 검증 및 완료

- fixture 검사: 휴식→시작 대기→진행, 실패→재시도, 중지 응답 유실, 중복 탭, 6시 경계, 장시간 세션.
- 실 DB가 준비되면 재실행 복원과 두 탭에서 같은 UID 동시 시작을 검증한다.
- 다른 UID의 세션을 현재 사용자의 세션으로 표시하지 않는다.
- 린트·타입 검사 및 `reports/02.md`. fixture는 tests 안에서만 사용하고 운영 코드의 데이터 연결을 바꾸지 않는다.
