# 05 — 출석·연차 (정책 확정 후)

지급·만료·본인 잔액 조회 기반은 200으로 구현했다. 사용·취소와 화면은 docs/DECISIONS.md의 미정 정책을 확정한 뒤 실행한다. 소유: LeaveScreen, leave 라우트, 후속 마이그레이션, tests/leave. 적용된 200 파일은 변경하지 않고 후속 번호를 사용한다.

## 시작 전 입력

- 출석 코어는 구현했다. 진행 중 포함 1초 이상 present, 종료된 0초 날짜 absent, 현재/미래 0초 pending이며 휴무는 별도 값이다. 이 작업에서는 출석 로직을 새로 만들지 않고 확정된 연차의 출석 대체 규칙만 연결한다.
- 확정: 월~일 중 6일 목표 달성 시 주당 연차 1개, 최초 지급 없음. 한 주는 월요일 오전 6시부터 다음 월요일 오전 6시 전까지다. 6번째 날 목표 달성 즉시 지급하고 바로 사용할 수 있다. UID+획득 주에 DB 고유 제약으로 중복 지급을 막는다.
- 만료: 획득 주의 다음 주 월요일 오전 6시부터 2주 뒤(획득 주 시작+21일). 예: 2026-10-26 주간 획득분은 2026-11-16 오전 6시 만료. 정각부터 사용 불가다.
- 확정: 진행 중 목표 달성도 인정한다. 양수 목표만 인정하며 휴무·미설정은 제외한다. 월별 지급이나 최초 지급을 임의로 추가하지 않는다.
- 사용 가능 날짜·신청 마감·취소 규칙·출석 대체 규칙.
- 만료가 다른 지급분의 차감 순서 및 잔액 부족 처리.

## 실행 범위

기반 완료: leave_grants에 UID+획득 주 UNIQUE, 고정 만료·획득 시각 제약, 본인 SELECT RLS를 적용했다. 클라이언트 쓰기 권한은 없다. src/data/leave.ts의 getLeaveStatus()가 DB에서 실제 달성 시각을 계산하고 누락 지급을 기록한 후 잔액과 내역을 반환한다. 진행 중 세션도 포함한다. 호출 없는 시각에는 DB 행이 생기지 않으며, 향후 화면은 진입·복귀·목표 달성 시 이 함수를 호출해야 한다. 매초 쓰기/폴링/cron은 추가하지 않는다. 아직 사용 기능이 없어 availableCount는 미만료 지급 건수다. 사용 기능 추가 시 사용분을 차감하도록 함께 확장해야 한다.

1. 확정 정책을 표와 날짜 예제로 문서화한 후 구현한다.
2. 지급 건별 잔액·만료·사용 배분을 최소 테이블로 저장한다. 정기 지급에 필요한 경우에만 스케줄 작업을 추가한다.
3. 연차 사용·취소는 UID를 서버에서 확인하고 트랜잭션/멱등 키로 중복 차감을 막는다.
4. 확정된 최소 인정 시간·판정 시점에 따라 공부 여부로 출석을 계산한다. 목표 달성을 출석 조건으로 사용하지 않는다. 목표 0분은 휴무로 구분하고 진행 중 세션의 인정 방식은 확정 정책을 따른다.
5. 연차 잔액·내역·사용/취소 UI를 만든다. 정책 미확정 화면을 실제 지급으로 대체하지 않는다.

## 완료 기준

지급 중복 실행, 동시 사용, 잔액 부족, 만료 직전/정각, 사용 취소, 6시 경계, 타인 UID 요청을 실제 DB에서 검증한다. 정책·코드·SQL·UI가 같은 예제 결과를 내야 한다. 린트·타입 검사와 `reports/05.md`를 남긴다. 미정 상태에서는 이 작업을 완료 처리하지 않는다.
