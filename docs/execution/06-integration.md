# 06 — 통합 및 배포 준비 (마지막 실행)

선행: 01~04의 변경과 보고서 확보. 05는 정책 확정 여부에 따라 별도 대기 가능하지만 그 경우 전체 기능 완료라고 표시하지 않는다.

## 통합 순서

1. 00 기준에서 01 → 02 → 03 → 04 순으로 변경을 병합하고, 확정된 경우 05를 병합한다. 독립 브랜치의 공통 파일 변경은 계약 기준으로 조정한다.
2. 실제로 존재하는 라우트만 `_layout.tsx`에서 간단한 내비게이션으로 연결한다. 로그인·방 선택 화면을 추가하지 않는다.
3. 모든 화면이 하나의 Supabase 클라이언트와 익명 세션을 사용하게 한다. UID를 화면별로 생성하지 않는다.
4. fixture나 미연결 stub이 운영 경로에 남았는지 검사한다. 미정 정책은 UI에서 대기로 표시한다.
5. 설정 누락·첫 인증 실패·프로필 재시도·DB 오류를 사용자가 복구할 수 있게 확인한다.
6. 기존 `UpdateNotice`를 공통 레이아웃에 한 번만 배치해 모든 화면에서 업데이트를 안내한다. app.json의 버전·배포 번호와 RELEASES.md 운영 절차를 보존한다.

## 시나리오 검증

- 4개 UID가 같은 방에 보이고 이름 중복에도 기록이 섞이지 않는다.
- A 시작 → B에 반영 → A 잠금/종료 → B의 A 시간 계속 증가 → A 복귀/중지 → B 확정 시간 반영.
- 같은 UID 두 탭 중복 시작과 중지 응답 유실 후 재시도에서 세션이 늘거나 종료 시각이 바뀌지 않는다.
- 재연결 시 놓친 변경을 재조회하고 6시 경계 합계가 일치한다.
- 무인증 요청·타인 수정은 거부하고 저장소 초기화는 새 UID로 처리한다.
- 미정인 목표 저장·출석·연차는 가짜 성공이나 결석으로 표시하지 않는다.

## 배포 준비

- `npm ci`, lint, typecheck, 담당 테스트, 웹 export를 실행하고 CI에 필요한 검사만 추가한다.
- iPhone 홈 화면용 manifest·아이콘·메타데이터를 연결한다. service worker와 오프라인 기록은 추가하지 않는다.
- Android 패키지 ID와 서명 절차를 확인하고 APK 빌드/설치/업데이트를 검증한다. 비밀 키는 레포 밖에서 관리한다.
- HTTPS 호스팅·Supabase 프로젝트 설정·익명 인증 활성화·DB 적용은 실제 수행 여부를 기록한다. 접근 정보가 없으면 로컬 배포 준비와 원격 배포 완료를 구분한다.
- iPhone Safari/홈 화면 및 Android 실기기 결과를 기록한다. 실기기가 없으면 미검증으로 남긴다.
- 초기 npm audit 경고의 현재 상태도 재확인하되 강제 SDK 변경은 하지 않는다.

`reports/06.md`에 검증 표와 남은 항목을 적고 README/SETUP-STATUS를 실제 구현 상태로 갱신한다. 정책 대기·외부 설정·실기기 검증 대기를 분리해 다음 작업을 알 수 있게 한다.
