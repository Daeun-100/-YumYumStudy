# 얌얌스터디 상세 기능 정책과 검증 기준

개정일: 2026년 10월 29일

상위 기준은 [제품 명세](SPEC.md)다. 이 문서는 그 제품 방향에 따른 기능별 입력 제한, 날짜와 상태 판정, 예외 처리, 권한과 검증 기준을 관리한다. 화면의 진입 경로와 조작은 [화면별 기능과 사용 흐름](CURRENT-FEATURES.md)에서 확인한다.

상세 규칙을 바꿀 때는 이 문서와 관련 화면 설명을 함께 갱신한다. 핵심 가치·기능 범위·제품 원칙이 달라지는 변경은 제품 명세도 갱신한다. 현재 정책은 이 문서를 기준으로 확인하며 제안과 과거 검사 결과를 확정 정책으로 해석하지 않는다. 구현과 운영 배포·실기기 검증 여부는 구분한다.

## 입장과 방 구분

- 실제 방 신규 사용자는 초대 코드 확인과 1~12자 이름 설정을 마쳐야 공부 기능을 사용할 수 있다. 이름은 앞뒤 공백을 제거하고 Unicode code point 기준으로 검증하며 중복을 허용한다.
- 코드 확인 후 앱을 닫아도 다음 실행에서 이름 설정부터 이어간다. 기존 사용자의 UID·기록·입장 자격은 유지한다.
- 초대 코드는 서버에 해시로 저장하며 원문을 앱 소스·Git·공개 환경 변수에 넣지 않는다. UID별 15분 동안 최대 5회 검증을 허용한다. 신규 UID 발급까지 막는 강한 가입 제한은 제공하지 않는다.
- 코드 변경은 기존 멤버의 입장 자격을 취소하지 않는다. 이름 설정을 마치지 않은 사용자는 친구 현황에 표시하지 않는다.
- 친구용 앱은 1번 실제 방을 사용한다. 테스트 버전은 기본 0번이며 0번·1번을 선택할 수 있다. 0번은 코드 없이 테스트 입장하고, 1번은 같은 초대 검증을 거친다.
- 방별 인증·UID·입장 상태·저장 데이터를 분리하며 기존 사용자의 방 번호를 바꾸거나 프로필을 합치지 않는다. 테스트 버전의 1번 방 조작도 실제 기록에 반영된다.
- 진행 중인 공부나 처리 중·미확인 요청이 있으면 방 전환을 제한한다. 전환 후 데이터와 구독을 다시 연결한다.
- 두 방은 같은 DB를 사용하므로 DB 구조 변경까지 격리하는 환경은 아니다.

## 타이머 및 동기화 요구사항

- 시작·종료 시각을 저장하고 차이로 시간을 계산한다. 화면의 초 단위 증가 횟수를 기록값으로 사용하지 않는다.
- 사용자별 진행 중 세션은 최대 하나다. 두 기기/탭에서 동시에 시작해도 서버가 하나만 허용한다.
- 시작은 서버 승인 후 성공 처리한다. MVP에서 오프라인 시작은 허용하지 않는다.
- 중지 요청은 재전송해도 중복 기록을 만들지 않는다. 통신 실패 시 미저장 상태와 재시도를 보여준다.
- 기본 타이머는 화면 숨김·잠금·앱 비활성 전환으로 세션을 중지하지 않는다. 백그라운드에서 매초 코드가 실행되거나 통신이 유지될 필요가 없다.
- 서버에 저장된 시작 시각과 현재 시각의 차이로 진행 중 시간을 계산한다. 기본 타이머는 앱 종료·네트워크 단절 후에도 세션을 유지하고 복귀 시 서버 기록으로 복원한다. Android 허용앱 모드의 자동 일시정지는 아래 별도 규칙을 따른다.
- 친구 현황은 실시간 변경 수신과 주기적 조회, 앱 복귀·재연결 시 재조회로 갱신한다. 기본 타이머는 갱신 신호 누락만으로 종료하거나 시간을 차감하지 않는다.
- 직접 일시정지 요청이 실패하면 종료 확정 전임을 표시하고 재시도를 제공한다. 직접 중지는 서버가 승인한 시각에 종료하며 요청 실패부터 승인까지의 시간도 포함된다. 허용앱 이탈은 저장된 이탈 시각으로 동기화한다.
- 기본 타이머에서 사용자가 중지를 잊으면 시간이 계속 누적된다. 최대 세션 시간이나 장시간 측정 확인, 사용자 기록 수정은 현재 제공하지 않는다.
- 오전 6시를 넘는 세션은 날짜 경계에서 나누어 합산한다. 서버 시각을 기준으로 하고 클라이언트 시각 조작을 신뢰하지 않는다.
- 친구 화면의 진행 중 시간도 서버 기록을 기준으로 계산한다. 갱신이 오래되거나 조회에 실패하면 마지막 확인 상태임을 표시하되 타이머를 휴식으로 바꾸지 않는다. 진행 중 시간과 종료 후 확정 기록을 구분한다.

### Android 허용앱 모드

- 기본 타이머는 사용정보·알림 권한이나 허용앱 선택 없이 시작할 수 있다. 필요한 권한이 모두 있고 허용앱을 선택한 경우 Android 감시를 준비한다. 시작한 세션의 기본 모드 여부를 저장해 복귀 시 잘못 자동 종료하지 않는다.
- 사용자는 허용앱 설정에서 권한을 설정하고 설치된 앱을 검색·선택한다. 선택은 기기에 저장하며 공부 중에는 바꾸지 않는다.
- 공부 중 홈·공부방의 허용앱 팝업으로 선택한 앱을 실행한다. 다른 허용앱도 스터디앱으로 돌아와 실행해야 한다.
- 허용되지 않은 앱·홈 화면으로 이동하거나 잠금·화면 꺼짐·권한 상실·감시 공백을 감지하면 로컬에서 일시정지한다. 복귀해도 자동 재개하지 않는다.
- 이탈 시각은 서버 시간 기준점과 기기 경과 시간을 사용해 저장한다. 서버는 본인·방·세션을 확인하고 시작 전이나 미래 시각을 허용하지 않으며, 재전송으로 종료 시간을 늘리지 않는다.
- 오프라인 등으로 서버 반영이 지연되면 저장된 중지 요청을 재처리한다. 미확인 중지가 남아 있으면 새 시작을 제한한다. 동기화 전까지 친구에게는 진행 중으로 보일 수 있다.
- 감시 대상 세션을 재발견해도 자동으로 감시를 다시 켜지 않는다. 감시 연결이 유실된 세션은 보수적으로 중지·정리하고 사용자가 직접 재개한다.
- 앱 사용 이벤트 감지는 실행 경로와 실제 공부 여부를 완벽히 증명하지 않는다. 분할 화면·PiP·제조사 절전 동작 등은 실기기 검증 대상이다.

## 목표·출석·연차 요구사항

- 무료 연차는 보상 연차와 별도로 매주 월요일 한국시간 06:00에 1개 지급하고, 다음 월요일 06:00 정각 소멸한다. 이월되지 않는다.
- 무료 자동 지급은 2026-11-02 06:00부터 시작한다. 2026-10-26 주간분은 사용자가 별도로 지시하기 전까지 지급하지 않는다.
- 아래의 6일 달성 및 21일 만료 규칙은 보상 연차에 해당한다. 중복 지급 방지는 사용자+획득 주+종류(free/reward) 기준이다.

- 목표는 요일별 0~1,440분 정수로 관리한다. 0분은 휴무이며 null(미설정)과 구분한다.
- 미설정은 아직 목표를 정하지 않은 초기 상태다. 요일 편집창은 즉시 시간 휠을 보여주고 공부 시간 또는 휴무를 선택한다. 설정한 목표를 미설정으로 되돌리는 UI는 제공하지 않는다.
- 최초 목표 저장은 서버 기준 현재 공부 날짜부터 즉시 적용하고 이미 공부한 시간도 포함한다. 기존 목표 이력이 있는 계정의 목표 변경은 서버 시각 기준 다음 공부 날짜 오전 6시부터 적용하고 현재·과거 목표 이력을 보존한다. 예를 들어 10월 26일 오전 2시에 변경하면 현재 공부 날짜는 10월 25일이며, 10월 26일 오전 6시부터 새 목표가 적용된다.
- 출석은 진행 중 시간을 포함해 해당 공부 날짜에 기록된 정수 초 합계가 1초 이상이면 present이며 목표 달성과 별개다. 목표 미달이어도 출석한다.
- 0초인 현재·미래 공부 날짜는 pending, 다음 오전 6시가 지나 종료된 공부 날짜는 absent로 표시한다. 휴무 여부(isRestDay)는 별도로 유지하므로 휴무일 공부도 출석으로 남긴다. absent는 공부 없음 표시이며 휴무일 불이익을 뜻하지 않는다.
- goalAchieved는 양수 목표에 대해서만 계산한다. 0분 휴무와 미설정은 null로 반환하고 자동 달성이나 0으로 나누는 달성률을 만들지 않는다.
- 현재 목표와 다음 공부 날짜의 예약 목표를 구분해 조회한다. 같은 적용일의 예약 목표를 반복 저장하면 하나의 버전을 갱신한다. 현재·과거 버전은 변경하지 않는다.
- 연차는 지급 건마다 수량과 만료 시각을 보존한다. 만료된 지급분은 사용할 수 없다.
- 보상 연차 획득은 월~일 중 6일 목표 달성 시 주당 1개이며 최초 지급은 없다. 주간 범위는 월요일 오전 6시부터 다음 월요일 오전 6시 전까지다. 6번째 날 목표 달성 즉시 지급하며 바로 사용할 수 있다. 당일 사용은 아래 보상 보호 조건을 따른다. UID+획득 주+종류에 고유 제약을 두어 재조회·동시 요청·7번째 달성에 중복 지급하지 않는다.
- 만료는 획득 주의 다음 주 월요일 오전 6시부터 2주 뒤다. 즉 획득 주 월요일 오전 6시 + 21일이며, 만료 시각 정각부터 사용할 수 없다. 예: 2026-10-26~2026-11-01 공부 주간에 획득한 연차는 2026-11-16 오전 6시 만료다. 같은 획득 주는 지급 요일과 무관하게 같은 만료 시각을 갖는다.
- 연차 차감은 서버 트랜잭션에서 처리한다. 중복 사용과 잔액 음수를 막는다.
- 진행 중인 공부도 연차 목표 달성에 포함한다. 목표가 양수인 서로 다른 공부 날짜 6일이 필요하며 휴무(0분)·미설정은 제외한다. getLeaveStatus 조회 시 누락된 지급을 기록하고, earnedAt은 실제 6번째 달성 시각으로 계산한다. 앱 미실행 중 과거 획득분도 같은 주·같은 만료로 복구한다. 시각 경과만으로 DB INSERT가 실행되는 구조나 백그라운드 지급 알림은 포함하지 않는다.
- 당일 사용 정책은 2026-10-27 확정하고 앱 소스·DB 구현을 완료했다. 앱 배포는 별도다. 현재 공부 날짜는 서버 승인 즉시 사용 완료, 미래 날짜는 예약이며 과거 날짜는 사용할 수 없다. 당일 사용은 해당 공부 날짜 전체에 적용하고 승인 시각은 별도로 보존한다.
- 미래 예약만 사용일 한국시간 06:00 전까지 취소/변경할 수 있다. 오늘로 변경하면 즉시 사용 완료이며 이후 취소/변경 불가다. 변경 실패 시 기존 예약을 유지한다. 취소 시 원래 만료일을 유지한다.
- 요청 승인 시점에 획득했고 미만료인 연차만 사용한다. 미래 예약은 사용일 시작 시각도 만료 전이어야 한다. 자동 선택은 만료 시각, 획득 시각, ID 순이며 날짜 변경은 기존 지급분을 유지한다.
- 사용자당 공부 날짜별 연차는 1개다. 연차 출석은 실제 공부 출석보다 우선하지만 실제 시간과 goalAchieved는 보존한다. 타이머를 자동 종료하지 않으며 연차 사용 후에도 공부할 수 있다. 미래 예약은 미리 출석 처리하지 않는다.
- 보상 인정 일수는 양수 목표 달성일 중 연차 사용일을 제외한 수다. 당일 제외 후 6일 미만이고 변경 전 해당 주 보상을 이미 획득했거나 획득 조건을 충족했다면 사용하는 연차 종류와 관계없이 당일 사용을 거부한다. 보상 조회 전이거나 기존 보상을 예약/사용/만료했더라도 같은 결과여야 한다. 당일 제외 후에도 6일 이상이면 허용하며 이미 획득한 보상을 회수하지 않는다.
- 보상 미획득·조건 미충족 상태에서는 당일 사용을 허용하되 그 날짜는 이후 목표를 달성해도 보상 인정 일수에서 제외한다. 휴무·미설정 여부만으로 새 사용 제한을 추가하지 않는다.
- 확인창에서 공부 날짜가 바뀌면 날짜와 상태를 갱신하고 다시 확인받는다. 성공 후 잔액·출석·보상 진행도를 함께 갱신한다. 확인창에는 공부 날짜와 종료 시각, 즉시 적용 및 취소·변경 불가를 함께 안내한다. 보상 보호 거절은 해당 날짜가 이번 주 보상 인정에 포함됐음을 설명한다.
- 만료 조회에는 별도 상시 서버가 필요 없지만 정기 지급·일별 정산에는 서버 작업 또는 지연 계산이 필요하다.

### 관리자 연차

- 관리자가 DB 운영 절차로 지정 사용자·날짜에 지급과 적용을 함께 처리한다. 앱 관리자 화면은 제공하지 않는다.
- 과거·오늘·미래 날짜에 적용할 수 있으며 획득 주와 만료일은 없다. 사용자·날짜별 연차 1개 제한은 유지한다.
- 일반 사용 가능 잔액과 자동 차감 대상에서 제외한다. 사용자 화면에 관리자 지급임을 표시하며 사용자는 변경·취소할 수 없다.
- 운영 사유는 비공개다. 실제 공부 시간과 목표 달성, 진행 중 타이머는 유지한다.
- 보상 인정 일수에서는 제외하되 이미 지급한 보상은 회수하지 않는다. 일반 사용자의 과거 사용 금지와 당일 보상 보호 정책은 그대로 유지한다.
- 상세 운영 절차는 [관리자 연차](../operations/ADMIN-LEAVE.md)를 따른다.

## 공유 포스트잇

- 입장과 이름 설정을 마친 구성원은 같은 방의 현재 공부 날짜에 포스트잇을 작성·조회·삭제한다. 다른 구성원의 포스트잇도 삭제할 수 있다.
- 내용은 최대 50자이며 노랑·분홍·연두 중 색상과 공부방 내 위치를 선택한다. 화면 크기가 달라도 상대 위치를 유지한다.
- 이전 공부 날짜의 포스트잇은 저장된 채 화면에서 숨긴다. 삭제한 포스트잇은 늦게 도착한 갱신으로 되살아나지 않는다.
- 같은 방에 변경 사항을 전달하고 복귀·재연결 시 서버 상태를 다시 조회한다.
- 작성 재시도는 같은 요청 ID를 사용한다. 사용자당 공부 날짜별 생성은 삭제한 건을 포함해 최대 30개다.

## 친구 부르기와 알림

- 공부방에서 같은 방의 입장·이름 설정을 마친 쉬는 친구에게 최대 40자 메시지를 보낸다. 본인과 공부 중인 친구는 대상에서 제외한다.
- 수신자 기준 5분에 한 번 전송하며 다른 발신자의 요청도 같은 제한을 적용한다.
- 수신 등록과 해제는 나 화면에서 기기별로 처리한다. 사용자당 등록 기기는 최대 5개이며 해제는 현재 기기에 적용한다. 처음 실행할 때 수신 권한을 강제로 요청하지 않는다.
- Android는 기기 알림을, iPhone은 HTTPS에서 홈 화면에 추가한 웹앱의 Web Push를 사용한다. Android 허용앱 측정 알림과 친구 부르기 수신 설정은 별개다.
- 알림을 누르면 공부방으로 이동하며 공부를 자동 시작하지 않는다. 다른 방의 알림으로 자동 전환하지 않는다.
- 같은 요청 ID의 재조회는 결과 확인이며 자동 재발송이 아니다. 전송 서비스 접수와 기기 도착을 구분하고, 접수를 실제 도착으로 보장하지 않는다.
- 운영자가 요청해 보내는 관리자 알림은 별도 운영 기능이며 일반 사용자의 친구 부르기 UI와 구분한다.

## 캐릭터와 보유 스킨

- 기본 캐릭터는 토끼·곰·고양이·강아지·말티즈·포메라니안·검은고양이다. 첫 입장과 프로필 수정에서 선택한다.
- 이름과 기본 캐릭터를 바꿀 수 있다. 다른 기본 캐릭터로 바꾸면 적용 스킨을 해제하고, 이름만 바꾸거나 같은 캐릭터를 선택하면 유지한다.
- 관리자가 지급한 이벤트 스킨은 사용자 보유 목록에 남는다. 사용자는 캐릭터별 목록과 미리보기를 보고 적용하거나 기본 모습으로 돌아간다.
- 다른 캐릭터의 보유 스킨을 적용하면 기본 캐릭터도 함께 변경한다. 홈·집중 화면과 친구 현황에 적용 상태를 반영한다.
- 홈·집중 이미지는 앱 에셋으로 배포한다. 현재 앱에 이미지가 없는 스킨은 업데이트 필요 상태로 안내하고 적용을 제한한다.
- 스킨 효과와 목표 달성 연출을 제공한다. 수박 재화 지급, 상점, 상품 구매, 유료 결제는 현재 확정 기능에 포함하지 않는다. [수박 보상 초안](../proposals/WATERMELON-REWARDS-DRAFT.md)은 검토 자료다.
- 상세 스킨 규격과 운영은 [캐릭터 스킨 명세](CHARACTER-SKINS-SPEC.md)와 [운영 절차](../operations/CHARACTER-SKINS-OPERATIONS.md)를 따른다.

## 상태 표시와 오류 복구

- 목표 달성의 대표 표시는 수박이며 문구나 접근성 설명을 함께 제공한다. 달성률 숫자는 100%를 넘을 수 있지만 막대 채움은 100%로 제한한다.
- 달력은 날짜 선택, 오늘 표시, 공부·달성·휴무·연차 상태를 구분한다. 연차와 목표 달성이 겹치면 보조 아이콘은 연차를 우선하고 실제 공부와 목표 달성 정보는 보존한다.
- 주간 차트의 목표는 핑크, 실제 공부 시간은 초록으로 표시한다.
- 연차일의 홈 목표 줄은 연차 탭으로 연결하며 실제 목표 달성 배지는 유지한다. 진행 막대 바탕은 `colors.leaveTrack`의 파랑 `#4E89C4`, 채움은 기존 초록이다. 오늘 사용과 미래 예약은 일정 목록에서 날짜별 달력으로 연결한다.
- UI 표면과 눌림·비활성 상태는 불투명 단색으로 표시한다. 반투명·유리 효과나 opacity로 친구 아바타를 흐리게 하지 않는다. 버튼 변형은 primary / secondary / raised이며 그림 위 raised 버튼은 불투명 크림색이다.
- 전환 탭은 연한 바탕·흰 선택 영역·초록 선택 글자를 사용한다. 목표 시간 색상은 `colors.goal`의 D1 핑크 `#FFA3A6`다.
- 달력의 선택은 진한 초록과 흰 숫자, 오늘은 작은 점(선택 시 흰색), 성과·일정은 보조 아이콘으로 구분한다. 선택 불가여도 상태 정보는 유지하고 기존 선택이 불가능해지면 해제한다.
- 로딩·저장 중에는 진행 상태를 표시하고 중복 제출을 제한한다. 오류 시 다시 불러오기나 동일 요청 재시도를 제공한다.
- 저장된 기록을 먼저 보여줄 때는 최신 기록 확인 중임을 안내한다. 친구 현황의 연결 끊김·갱신 지연도 현재 상태로 오인하지 않도록 표시한다.
- 목표 저장 실패 시 입력을 유지한다. 저장 결과가 불확실하면 최신 상태를 확인한 뒤 재시도하며 성공 전에 완료로 표시하지 않는다.

## 접근 권한

- 설치 또는 웹 접속 후 익명 인증을 자동 수행한다. 저장된 인증 세션을 재사용하며 UID만으로 타인 인증을 대신할 수 없다.
- 친구용은 고정 실제 방 하나를 사용하며 입장을 마친 구성원만 같은 방 현황을 조회한다. 사용자용 방 생성·검색·선택·초대 코드 발급·가입 승인 UI는 제공하지 않는다. 개발용 방 분리는 입장과 방 구분 절을 따른다.
- 본인 목표와 세션에만 변경 권한을 갖는다. 타인 기록과 연차 잔액을 직접 변경할 수 없다.
- 연차 지급, 최종 시간 정산, 출석 판정은 서버에서 수행한다. 포스트잇과 스킨, 알림 요청도 서버에서 사용자와 방 권한을 검증한다.
- API에 공개하는 모든 테이블에 RLS(행 단위 접근 권한)를 적용한다. 인증 세션 없는 요청과 타인 기록 변경을 거부한다. 익명 인증만으로 실제 방의 공부 현황에 접근할 수 없으며 입장과 이름 설정 완료 여부도 확인한다.
- 사용자 ID는 서버 인증 세션의 UID로 확인한다. 요청에 담긴 UID나 표시 이름을 그대로 신뢰하지 않는다.
- MVP에 로그아웃 UI는 없다. 앱 데이터·브라우저 저장소 삭제 또는 다른 기기 사용 시 새 UID가 생성될 수 있다. 이름이 같아도 기존 기록과 자동 병합하지 않는다. UID는 사람이나 영구적인 기기 식별자가 아니다.
- 예상 사용자는 4명이지만 신규 UID를 기존 4명으로 자동 판별하거나 가입을 4명으로 제한하지 않는다. 초대 코드는 입장 검증이며 사람 단위 계정 식별이나 영구적인 가입 인원 제한을 보장하지 않는다.

## 버전 및 업데이트 안내

- 작성자가 새 APK/웹을 배포한 후 Supabase의 플랫폼별 배포 정보를 활성화하면 새 버전 안내를 표시한다.
- 실행·복귀 시 확인하고 사용 중 주기적으로 확인하지 않는다. 확인 실패 시 수동 재시도를 제공한다. Android는 다운로드 링크, 웹은 새로고침 버튼을 제공한다.
- 표시 버전과 단조 증가하는 배포 번호를 관리하고 더 높은 배포 번호만 안내한다. 안내를 나중으로 미룰 수 있다.
- 꺼진 앱에 OS 푸시 알림을 보내거나 자동 설치하지 않는다. 운영 절차는 [버전 및 배포 운영](../operations/RELEASES.md)을 따른다.

이 절의 OS 푸시 제외는 업데이트 안내에 해당한다. 친구 부르기와 운영자 요청 알림은 별도 기능이다.

- 기존 APK와 호환되는 변경은 master 배포 흐름의 호환성 검토를 거쳐 OTA로 제공할 수 있다. 기본 앱 버전과 versionCode는 유지하며 성공한 배포는 `vX.Y.Z-rN`으로 기록한다.
- 새 APK는 `X.Y.Z`와 Android versionCode를 올린다. `rN`은 배포 식별자이며 사용자 표시 버전이나 APK 대소 비교 기준으로 쓰지 않는다. GitHub Latest는 APK 릴리스를 유지한다.
- 테스트 버전은 운영 업데이트 안내를 조회하지 않는다. 로컬에서 운영 업데이트를 직접 게시하지 않는다.

## 제외 범위 (상세)

별도 로그인·회원가입 화면, 이메일/비밀번호·소셜 로그인, 일반 사용자용 방 생성·검색·선택·초대 코드 발급·가입 승인, 여러 스터디방 운영, 기기 간 UID 이전·계정 복구, 스토어 공개, iOS 네이티브 배포, 결제, 실시간 대화방, 공개 가입 커뮤니티, 부정행위 완전 방지, 오프라인 신규 공부 시작, 사용자 공부 기록 편집, 다른 앱 자체의 실행 차단은 현재 범위에 포함하지 않는다.

초대 코드 입력, 테스트 버전의 방 선택, 공유 포스트잇과 친구 부르기, 진행 중 기본 타이머의 연결 단절 후 유지, Android 이탈 중지 요청의 재동기화는 확정 기능이다. 수박 재화·상점·상품 구매·플래카드는 검토 중인 초안이며 추가 정책 확정이 필요하다.

## 기능 검증 기준

아래 항목은 검증해야 할 기준이며 완료 체크리스트나 전체 실기기 검증 완료 선언이 아니다.

- Android 실기기에 APK 설치, iPhone Safari 및 홈 화면 실행을 확인한다.
- 별도 로그인·방 생성 화면 없이 UID를 발급받고, 초대 코드·이름·캐릭터 설정 후 입장한다. 재실행·새로고침에서는 저장된 세션과 입장 단계를 재사용한다.
- 서로 다른 4개 UID의 목표·세션·일별 합계가 서로 맞고, 이름 중복·변경으로 기록 소유자가 바뀌지 않는다.
- 인증 없는 DB 요청 및 다른 UID의 기록 변경은 거부된다. 저장소 초기화 시 새 UID로 처리하고 이전 기록을 자동 인계하지 않는다.
- 중복 시작·중복 종료·6시 경계·이탈·강제 종료·통신 실패 후 복귀를 검증한다.
- 기본 타이머는 이탈·잠금·앱 종료·연결 단절 후 시간 누적과 복귀 복원을 검증한다. 직접 중지 실패·재시도·승인 시각 기준 종료를 검증한다.
- Android 허용앱 모드는 앱 내부 실행 경로, 앱 이탈·잠금·권한 상실 시 중지, 자동 재개 방지, 오프라인 중지 동기화와 재시작 복구를 검증한다.
- 출석·연차 지급·차감·취소·만료 경계와 권한, 당일 보상 보호, 관리자 적용과 무료 연차 지급 시작일을 검증한다.
- iPhone의 앱 구별·차단 미지원과 저장 실패 상태를 화면에서 명확히 안내한다.
- 포스트잇 생성·삭제·날짜 경계·방 격리·재시도와 다른 화면 크기에서의 위치를 검증한다.
- 친구 부르기의 대상 제한·쿨다운·중복 방지·기기별 해제와 실제 알림 도착·터치 이동을 검증한다.
- 스킨 보유 권한·다른 캐릭터로 적용·해제·이미지 미지원 상태와 홈·집중·친구 표시를 검증한다.
- 테스트 버전의 방 전환, 인증·데이터 분리와 실제 방 입장 검증을 확인한다.

### 연차 경계·동시성 검사

| 사례 | 기대 결과 |
| --- | --- |
| 10월 28일 02:00에 오늘 사용 | 10월 27일 공부 날짜에 적용. 06:00부터 같은 날짜 신규 사용 거부 |
| 당일 낮 획득·만료 직전/정각 | 획득 후 보상 보호 조건을 만족하면 사용 가능. 만료 정각은 거부 |
| 6번째 달성일에 오늘 사용하여 인정 일수가 5일이 됨 | 보상 조회 전후·지급분 종류·기존 보상 상태와 관계없이 거부 |
| 7일 달성 후 오늘을 제외해도 6일이 남음 | 오늘 사용 허용. 연차일의 실제 시간·목표·진행 타이머 보존 |
| 미래 예약을 오늘로 변경 | 즉시 USED, 취소·변경 불가. 실패 시 기존 예약 보존 |
| 같은 날짜 동시 사용·revision 충돌 | 날짜당 하나만 사용하고 오래된 새 요청은 거부 |
| 승인 응답 유실 후 재시도·확인 중 06:00 경과 | 같은 ID로 중복 차감 방지. 새로운 날짜를 자동 적용하지 않음 |

서버 재현 SQL은 `supabase/tests/same_day_leave.sql`, `leave_requests.sql`, `leave_reschedule.sql`, `leave_concurrency_holder.sql`, `leave_concurrency_contender.sql`을 확인한다. 화면 샘플·SQL 롤백·실제 기기 검증 결과는 각각 구분한다.
