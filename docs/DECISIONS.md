# 결정 기록

## 확정

- 프로젝트의 최우선 구현 원칙은 간단함이다. 현재 MVP에 필요한 최소 구조와 의존성을 사용하고 미래 확장을 위한 기능·추상화를 미리 추가하지 않는다.
- Android APK 직접 배포 + iPhone 웹앱.
- 업데이트는 앱 안에서 안내한다. 작성자가 배포 완료 후 플랫폼별 배포 정보를 활성화하고, 앱은 실행·복귀 시 확인한다. 사용 중 주기적 확인, 꺼진 앱 OS 푸시와 강제/자동 설치는 제외한다.
- Expo 공통 코드, Supabase 공유 백엔드.
- 로그인·회원가입 화면 없이 Supabase 익명 인증으로 UID를 자동 발급하고 세션을 저장한다. 이름은 표시용이다.
- 모두 작성자가 포함된 고정 방 하나에 자동 참여한다. 방 생성·검색·선택·초대·가입 승인은 제외한다.
- 예상 사용자는 4명이며 가입 인원 제한은 두지 않는다. 저장소 삭제·기기 변경 시 새 UID가 될 수 있고 MVP는 이전·복구·이름 기반 병합을 제공하지 않는다.
- 화면 이탈·잠금·앱 종료·연결 단절에도 타이머를 유지하고 직접 중지하면 종료한다. 다른 앱 사용 시간도 포함한다. (2026-10-26 변경)
- 중지는 서버 승인 시각에 확정한다. 통신 실패 시 미확정 상태와 재시도를 표시한다.
- 비용과 운영 부담을 줄이되 무료 한도와 서비스 정책을 확인하며 운영.

## 구현 전 확인

| 항목 | 결정할 내용 | 임시 처리 |
| --- | --- | --- |
| 표시 이름 | 초기 기본 이름과 변경 UI | UID와 분리하고 이름 중복 허용 |
| 출석 | 목표 달성 기준인지, 최소 시간 기준인지 | 판정 구현 보류 |
| 목표 | 0분/휴무 허용, 변경 적용 날짜 | 과거 목표 보존 원칙만 확정 |
| 연차 지급 | 주기, 수량, 시작 시 지급 여부 | 자동 지급 구현 보류 |
| 연차 사용 | 신청 마감, 과거 날짜, 취소, 출석 대체 | 차감 구현 보류 |
| 연차 만료 | 기간, 만료 시각, 선입선출 기준 | 지급 건별 만료 모델만 설계 |
| 연결 상태 | heartbeat 간격, 연결 표시 유효기간 | 시간 누적과 분리, 실기기 검증 후 결정 |
| 중지 누락 | 최대 세션 시간, 복귀 확인, 기록 수정 | 직접 중지 전까지 유지, 자동 종료 없음 |
| Android 확장 | 허용 앱·차단의 필수 여부 | MVP 이후 별도 검증 |
| 배포 | 호스팅 제공자, 주소, Supabase 프로젝트 | 외부 생성/배포 전 결정 |

미정 정책을 코드의 임의 상수로 확정하지 않는다. 결정 후 이 문서와 제품 명세를 함께 수정한다.
