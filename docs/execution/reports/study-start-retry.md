# 타이머 시작 요청 영속화

- 화면 없이 시작 코어와 앱 초기화 복구를 연결했다. 시작 API는 startStudy(requestId)에서 startStudy()로 바뀌었다.
- Expo SDK 58 공식 Crypto 문서를 확인하고 expo install로 expo-crypto를 설치했다. randomUUID로 요청번호를 생성한다.
- UID별 저장 키를 사용한다. 저장 성공 후 서버에 보내고 성공 응답의 UID 확인 후 정리한다. 저장 실패, 손상, 통신 실패, 정리 실패 시 임의의 새 번호로 바꾸지 않는다.
- IdentityProvider는 프로필 준비 후 resumePendingStudyStart를 실행한다. 미완료 요청이 없는 일반 실행에서는 시작 RPC를 보내지 않는다. 실패는 기존 초기화 오류/재시도로 표시한다.
- 신규 자동 테스트는 서버 승인 후 응답 유실, 프로세스 재생성 후 동일 번호 복원, 원래 세션 종료 후 재전송, 중복 탭, 복구와 시작 동시 호출, 저장 실패/손상, 정리 실패, UID 분리를 검사한다. 가짜 서버/저장소를 사용하는 테스트이며 실제 기기 강제 종료나 실 Supabase 응답 유실을 재현한 결과는 아니다.
- 타이머 화면은 아직 구현하지 않았다. 화면 구현 시 getToday로 복구 후 최신 상태를 조회해야 한다. 과거 시작 요청의 복구 응답이 종료된 세션일 수도 있다.
- 검증: 전체 자동 테스트 27개, 타입 검사, 린트, 웹 export 통과. 실제 기기 종료/재설치 및 여러 브라우저 탭에서의 장애 재현은 미실행이다.
- 웹 여러 탭의 localStorage 원자적 잠금은 범위 밖이다. 서버의 사용자별 진행 세션 유일성이 중복 진행을 차단한다. 저장 공간/앱 삭제 시 요청번호 복원은 보장하지 않는다.
