# YumYumStudy 이슈 추가

## 대상과 범위

기본 저장소는 `Daeun-100/-YumYumStudy` (https://github.com/Daeun-100/-YumYumStudy) 이다. 이 프로젝트에서 “이슈로 추가해줘”라는 요청은 실제 이슈 생성 승인이다. 제목·본문을 정리한 다음 추가 확인 없이 등록한다. 다른 저장소를 명시하면 사용자 지시를 따른다. 다른 프로젝트의 모호한 요청에 이 저장소를 적용하지 않는다.

이슈 등록만 요청했다면 코드 수정, 브랜치 생성, PR 작성, 기존 이슈 변경은 하지 않는다.

## 내용 작성

- 사용자 메시지와 관련 대화에서 내용을 파악한다. 짧아도 핵심이 명확하면 진행한다. 주제 자체를 알 수 없는 경우에만 질문한다.
- 제목과 본문은 기본적으로 한국어로 작성한다. 제목은 문제나 원하는 변경이 드러나도록 간결하게 쓰고, 사용자가 지정한 표현과 형식을 우선한다.
- 본문에는 요청 요약과 기대 동작을 담는다. 버그라면 제공된 현재 동작, 재현 단계, 환경을 포함한다. 필요한 항목만 사용하고 단순 요청을 과도한 양식으로 늘리지 않는다.
- 제공되지 않은 재현 단계, 원인, 기기, OS, 로그, 우선순위를 사실처럼 만들지 않는다. 추정은 추정이라고 표시한다. 코드 확인은 본문 정확도에 필요한 범위로 제한한다.
- `.github/ISSUE_TEMPLATE/`에 적절한 템플릿이 있으면 반영한다. 라벨, 담당자, 마일스톤, 프로젝트는 사용자가 지정했거나 저장소 지침에 명시된 경우에만 설정한다.

## 등록 및 확인

1. 사용 가능한 GitHub 커넥터의 이슈 검색·생성 도구를 우선 사용하며 현재 제공되는 스키마를 확인한다.
2. 가능하면 생성 전에 해당 저장소의 열린 이슈에서 동일한 요청을 검색한다. 명백히 같은 이슈가 있으면 기존 링크를 알려준다. 단순히 관련된 이슈라는 이유로 새 요청을 생략하지 않는다. 사용자가 별도 생성을 명시하면 따른다.
3. 커넥터로 수행할 수 없고 인증된 `gh` CLI가 있으면 `gh issue create --repo Daeun-100/-YumYumStudy --title ... --body-file ...`를 사용한다. 본문은 임시 UTF-8 파일에 실제 줄바꿈으로 저장한다. 인자를 안전하게 인용하고 사용자 내용을 쉘 코드로 보간하지 않는다.
4. 생성 결과가 시간 초과 등으로 불명확하면 같은 제목의 최근 이슈를 조회해 생성 여부를 확인한다. 존재하지 않는 것이 확인된 경우에만 한 번 재시도한다. 여전히 불명확하면 중복 생성을 멈추고 상황을 알린다.
5. 인증·권한 문제로 등록하지 못하면 작성한 제목·본문과 실패 이유를 제공한다. 성공하지 않았는데 등록했다고 말하지 않는다.
6. 성공 응답에서 이슈 번호와 URL을 확인하고 `[#번호 제목](URL)` 링크를 짧게 제공한다.

스킬 검증 목적으로 실제 테스트 이슈를 만들지 않는다.
