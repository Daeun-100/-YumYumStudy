# 초대 코드와 이름 설정 — 2026-10-26

## 구현 및 실제 DB 적용

- 250_room_onboarding.sql, 251_completed_members.sql을 Supabase에 적용했다.
- 신규 사용자: 익명 인증 → 초대 확인 모달 → 이름 설정 → 홈. 이름 설정 전 화면과 공부 RPC를 차단한다.
- 기존 프로필은 UID/기록/입장 자격을 보존하며 이름을 한 번 다시 설정한다.
- 실제 방 초대 코드는 미등록. 신규 입장은 INVITE_NOT_CONFIGURED 응답으로 차단된다.
- 개발 방 0은 테스트 입장 버튼으로 진행하며 실제 방 1로 이동할 수 없다.
- 이름은 trim 후 Unicode code point 1~12자, 중복 허용. 홈에서 변경 가능.
- 입장 상태는 서버에서 복원한다. 코드 확인 후 종료 시 이름 설정부터 이어진다.
- 코드 정답은 private table의 bcrypt hash로 보관하고 클라이언트 조회 권한은 부여하지 않는다.
- UID별 15분/5회 검증 제한. 신규 UID 발급까지 막는 강한 남용 방지는 이번 범위가 아니다.
- 이름 미완료 멤버는 친구 조회와 profiles RLS에서 제외한다.

## 검증

- lint, tsc --noEmit 통과. 자동 테스트 총 47개 통과. 배포용 웹 export 성공.
- 실제 DB room_onboarding.sql 통합 검사 통과: 미등록/오답 차단, rate limit,
  legacy ensure_profile 우회 차단, 입장 전 RLS/RPC 차단, 단계 복원, 이름 제한/중복/변경,
  방 이동 거부, 이름 미완료 사용자 숨김, 코드 변경 후 기존 멤버 유지.
  검사 사용자/설정/기록은 transaction rollback으로 모두 되돌린다.
- 실제 브라우저: 개발용 첫 모달 → 이름 설정 → 새로고침으로 이름 단계 복원 → 저장 → 홈,
  새로고침 자동 입장 → 이름 변경 반영 확인.
- UI 검사용 0번 방 프로필 ‘테스트친구’ 1개를 생성했으며 공부 기록은 만들지 않았다.
- 배포용 웹을 localhost:8092에서 열어 실제 초대 코드 입력란 및 입장 버튼 표시 확인.
- Android 실기기/키보드 동작과 APK 설치는 미검증. 친구용 원격 웹/APK는 미배포.
