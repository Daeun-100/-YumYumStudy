# 이벤트 기록과 예약

프로젝트의 `docs/operations/EVENT-OPERATIONS.md`를 읽고 요청한 작업에 해당하는 절차를 따른다. 행사 기획·결과는 `docs/events/`에, 실제 예약과 지급 원본은 서버에 저장한다. 문서 작성과 실제 예약을 구분한다.

- 지원 자동 작업은 `grant_skins`, `set_backgrounds`다. 소품·재화 수집·교환·배너·효과 등은 문서에 기록할 수 있지만 미지원 기능을 예약했다고 보고하지 않는다.
- 날짜는 한국 시간으로 해석한다. 연도·시각·대상 방·선물 또는 배경·화면·시작과 종료를 문서와 대화에서 확정한다. 빠진 필수 정보만 묻고 이미 승인한 요청을 다시 승인받지 않는다.
- 서버 카탈로그와 이미지 배포 준비를 확인한다. 활성화는 관리자 요청과 배포 확인을 근거로 한다. 파일이 저장소에 있다는 사실만으로 배포됐다고 판단하지 않는다.
- 생성에는 새 UUID를 쓰고, 동일 요청의 불명확한 결과를 재조회·재전송할 때는 같은 UUID와 같은 입력을 유지한다. 입력 JSON은 비공개 임시 파일에 작성해 CLI `--request`로 전달한다.
- CLI는 비공개 환경의 서비스 키를 사용한다. 키가 없고 연결된 Supabase 도구를 사용할 수 있으면 같은 관리자 RPC를 `execute_sql`로 호출할 수 있다. 이때 신뢰된 JSON을 안전하게 SQL 리터럴로 인코딩하고 임의 사용자 SQL을 실행하지 않는다. 키를 조회·출력·문서화하지 않는다.
- 변경에는 `replaces`를 사용한다. 스킨 대상 명단은 원본 유지다. 진행 중 배경 변경은 원래 시작 시각을 유지하고 종료·배경을 바꾼다. 완료 지급의 취소는 회수가 아니다.
- 응답이 끊기면 먼저 작업 ID를 조회한다. 실패나 미확정 실행을 관리자 요청 없이 재지급하지 않는다. 사용자가 복구를 요청하면 해당 작업의 실패·미처리 대상만 재실행한다.
- 서버 작업과 Cron을 재조회한 다음 문서에 작업 ID·확인 시각·집계를 갱신한다. 문서 갱신 실패와 서버 작업 실패를 각각 보고한다. 개인별 UUID·명단은 이벤트 문서에 넣지 않는다.
- 조회는 실제 서버 상태를 근거로 한다. 이 스킬 실행 중만 조회하며, 사용자가 별도 요청하지 않은 상시 감시·알림을 만들지 않는다.
