# 00 공통 기반 결과

2026-10-26. 공통 코드 구현·자동 검사·웹 브라우저 UID 복원 검증 완료. 고정 방 DB 연결과 Android 실기기는 대기다.

## 구현

- Expo Router: index.ts 진입점, src/app/_layout.tsx, 임시 src/app/index.tsx. 기존 App.tsx를 제거했다.
- 공통 IdentityProvider/useIdentity: loading, uid, profile, StudyError, retry. 다른 화면은 이 상태를 재사용한다.
- Supabase SDK 단일 클라이언트와 설정 검증. 웹 localStorage/네이티브 AsyncStorage로 인증 세션을 저장한다. 네이티브 토큰 갱신은 활성 상태에서만 수행한다.
- ensureAuthIdentity는 저장 세션을 서버에서 확인하고 없을 때만 익명 인증을 수행한다. 동시 초기화는 같은 요청을 공유한다.
- 기존 UID 표식이 있는데 세션이 없거나 UID가 다르면 새 사용자를 만들지 않는다. 네트워크/인증 오류에서도 자동 재가입하지 않는다. 최초 가입 요청의 응답 자체가 유실되는 경우 서버 생성 여부를 확인할 수 없는 한계는 남는다.
- ensureIdentity는 인증 후 ensureProfile을 호출한다. 후속 DB 작업 전에는 NOT_CONFIGURED로 고정 방 연결 대기를 표시한다. UID 성공과 방 입장 성공을 혼동하지 않는다.
- contracts.ts: UID/Profile/StudySession/GoalWeek/DayRecord/RoomMember/Snapshot/StudyError 및 목표 배열 검증.
- study-day.ts: KST 06:00 기준 날짜와 날짜 구간·겹치는 정수 초 계산.
- clock.ts: 서버 snapshot과 monotonic 경과로 표시 시각 계산. 복귀 시 다음 snapshot으로 기준을 갱신해야 한다.
- src/data/study.ts의 공통 함수 stub: 미연결 오류, 목표 저장은 POLICY_PENDING. 가짜 기록은 반환하지 않는다.
- UpdateNotice를 공통 레이아웃으로 이동했다. 업데이트 주기 조회 제거 요청도 포함해 실행·복귀만 확인한다.

## 의존성과 명령

Expo SDK 58 호환 expo-router, expo-constants, expo-linking, react-native-safe-area-context, react-native-screens 및 Supabase JS, AsyncStorage, URL polyfill을 설치했다. 추가 테스트 도구는 설치하지 않았다.

- npm test: Node 기본 테스트 러너와 type stripping. 12개 통과.
- npm run typecheck / npm run lint / npm run export:web: 통과.
- npm run web: 로컬 실행. 이번 검증은 localhost:8082에서 진행했다.

## 실제 검증

- 실제 브라우저 첫 진입에서 익명 사용자 UID `03e6343c-dd1c-4df8-8af7-4b6b0282deb9` 발급.
- 같은 주소 새로고침 후 같은 UID 복원. 재시도도 같은 UID 사용.
- EXPO_NO_DOTENV=1인 별도 로컬 서버에서 설정 누락 문구와 재시도 버튼 렌더링, 재시도 후 크래시 없음 확인. 이 검사는 인증 사용자를 생성하지 않았다.
- fixture로 동시 호출 한 번 생성, 기존 UID 복원, 인증/통신/저장 오류, 재시도, 6시 경계, 다일 세션 분할, 음수 시간 방지, 서버 시계 기준, 잘못된 설정 거부 검사.
- 스크린샷: docs/images/foundation-uid-restored.jpg, foundation-missing-config.jpg.
- Android 빌드·실기기, 프로필 DB/RLS·기록 저장·Realtime은 이번 단계에서 검사하지 않았다. 초기 audit high 5건은 설치 출력에서도 남아 있다.

## 01 인계

1. src/data/profile.ts의 ensureProfile을 인증 UID 기반 멱등 RPC로 교체한다. UI와 identity 로직을 고치거나 새 익명 클라이언트를 만들 필요 없다.
2. src/data/study.ts를 CONTRACT.md대로 구현한다. subscribeStudyChanges는 현재 disconnected를 알리고 NOT_CONFIGURED를 throw하므로 소비 화면이 실패를 표시해야 한다.
3. 타입은 src/lib/contracts.ts, 에러는 StudyError를 사용한다. 다른 파일에 같은 모델을 복제하지 않는다.
4. 6시 계산 SQL 검증 예제는 tests/foundation.test.mjs와 맞춘다. 목표 저장·출석·연차 미정 정책은 유지한다.
5. 010_app_releases.sql은 원격 프로젝트에 수동 적용 완료다. DB 기본 마이그레이션이 기존 테이블을 삭제하거나 재생성하지 않게 한다.

## 병렬 세션 인계

02는 index 라우트를 TodayScreen으로 대체한다. 03은 room 라우트/화면을 추가한다. 04는 목표·기록 라우트를 추가한다. 공통 _layout과 타입·SDK 설정을 동시에 고치지 않는다. 필요한 내비게이션 연결은 통합 담당자에게 요청한다. fixture 검증과 실제 DB 연동 완료는 보고서에서 구분한다.
