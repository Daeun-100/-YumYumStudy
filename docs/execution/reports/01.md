## 구현 파일

- `supabase/migrations/100_study_core.sql`: 고정 방, 프로필, 공부 세션, 시작 요청 매핑, 목표 버전. 연차·범용 그룹·합계 캐시 테이블은 만들지 않았다.
- `src/data/profile.ts`: ensure_profile RPC로 고정 방 프로필 확보.
- `src/data/study.ts`: 오늘/시작/종료/방/목표/기록 RPC 및 Realtime 구독 연결. 목표 저장은 POLICY_PENDING 유지.
- `src/data/rpc.ts`: SDK 요청·15초 제한·한국어 StudyError 변환.
- `src/data/decode.ts`: 응답 형식 검증. 잘못된 응답을 빈 기록/0초로 숨기지 않는다.
- `src/lib/contracts.ts`: DayRecord.runningSeconds 추가. 미종료 세션의 과거 공부 날짜 부분도 잠정 시간으로 표시할 수 있다.
- `scripts/check-study-core.mjs`: 실제 서비스 통합 검사. 명시적인 --run에서만 테스트 사용자를 생성한다.
- `supabase/tests/core_boundaries.sql`: 테스트 프로필을 사용한 날짜/목표 SQL 검사. fixture는 트랜잭션 롤백으로 보존하지 않는다.
- 기존 IdentityProvider의 effect 내부 동기 setState 린트 문제를 재시도 핸들러로 옮겨 수정했다.

## DB 규칙

인증 없는 공부 데이터 조회와 RPC 실행은 거부한다. 익명 인증된 사용자는 고정 방의 현황을 조회한다. 클라이언트의 테이블 직접 쓰기는 전부 거부하며 프로필 생성과 시작/종료만 인증 UID를 확인한 함수로 처리한다. SECURITY DEFINER 함수는 search_path를 비우고 PUBLIC/anon 실행 권한을 제거했다. 내부 계산 함수와 요청 매핑도 클라이언트에게 노출하지 않는다.

시작/종료는 사용자 프로필 행을 잠가 직렬화한다. 진행 중 세션은 부분 unique index로 하나만 허용한다. 다른 시작 요청이 같은 진행 세션을 반환한 경우에도 요청→세션 매핑을 남겨, 종료 후 늦게 도착한 재시도가 새 세션을 만들지 않는다. 중복 종료는 최초 종료 시각을 그대로 반환한다.

읽기는 같은 SQL snapshot과 기준 시각을 사용한다. closedSeconds는 종료 세션만, runningSeconds는 기준 시각의 미종료 부분만 합산한다. 오늘 실시간 표시는 activeSession으로 다시 계산할 수 있지만 runningSeconds를 중복해서 더하면 안 된다. 일별 목표는 적용일 기준 최신 버전에서 조회하고 출석은 pending으로 유지한다.

## 실제 검증 결과

- 원격 프로젝트의 SQL Editor에서 100 마이그레이션 적용 성공. 고정 방 `얌얌스터디` 확인. 010 업데이트 테이블은 보존했다.
- 무인증 SELECT/RPC 거부, 타인 프로필·목표 위조와 직접 세션 시각 쓰기 거부, 타인 종료 거부.
- 프로필 중복 생성 없음, 목표 미설정 null 7개 반환.
- 동시에 다른 requestId로 시작해도 진행 세션 하나. 동일 요청 재전송도 동일 세션.
- 동시 중복 종료에서 동일 종료 시각 유지. 종료 후 새 세션 시작, 이전 요청 늦은 재전송은 이전 종료 세션 반환.
- B가 A의 진행 세션을 조회하고 Realtime INSERT/UPDATE 수신. 첫 검사에서는 전달 시간 초과가 있었고, publication/SELECT/RLS 설정 확인 후 재검사에서 모두 통과했다. 연결 자체만으로 전달 성공을 판단하지 않았다.
- 오늘/기록 합계 일치, pending 출석과 null 목표, 종료 후 runningSeconds=0 확인.
- SQL fixture 검사: 05:59:59/06:00, 닫힌 세션 30분씩 분할, 하루 전체 진행 86400초, 현재 날짜 1800초, 미래 날짜 0초, 목표 적용일·요일·과거 이력. 검사 후 rollback 성공.
- 실제 웹의 기존 UID로 고정 방 프로필 연결 성공.
- `npm test` 15개, 타입 검사, 린트, 웹 export 통과.
- 로컬 Docker CLI는 있으나 엔진이 실행 중이지 않아 새 로컬 DB 적용은 미검증이다. 실제 원격 DB에서 검증했다. Android/iPhone 실기기는 미검증이다.

## 후속 인계

02는 getToday/startStudy/stopStudy와 useIdentity로 실제 타이머 화면을 만든다. 03은 getRoom/subscribeStudyChanges로 친구 화면을 만든다. 구독 완료/재연결/변경 알림 후 snapshot을 다시 조회하고 조회 중 알림 유실을 막는 것은 소비 화면 담당이다. 04는 getGoals/getHistory를 사용하며 목표 저장 정책이 정해지기 전에는 저장을 성공 처리하지 않는다.

공통 계약의 runningSeconds 변경을 읽고 오늘 실시간 시간과 중복 합산하지 않는다. 원격에 010/100을 SQL Editor로 수동 적용했으므로 재실행하지 않는다. 추후 CLI 사용 전 적용 이력을 맞춘다. 목표 저장·출석·연차·표시 이름 편집은 추가하지 않았다.
