# 05 — 출석·연차 당일 사용 변경

정책 확정: 2026-10-27. 앱 소스·DB 구현 및 로컬 검증 완료. 배포 앱 업데이트는 별도다. 검증 결과는 `reports/same-day-leave.md`를 따른다. 정책 기준은 `../DECISIONS.md`와 `../SPEC.md`다. 기존 미래 예약·취소·변경과 연차 화면은 구현되어 있다. 기존 마이그레이션을 수정하지 않고 후속 마이그레이션으로 변경한다.

## 정책과 처리 순서

1. 서버 시각으로 한국시간 06:00 기준 공부 날짜를 판단한다. 과거는 거부, 당일은 즉시 USED, 미래는 SCHEDULED다. 미래 예약도 사용일 06:00부터 USED다.
2. 승인 시점에 획득했고 미만료인 지급분만 허용한다. 미래 예약은 사용일 시작도 만료 전이어야 한다. 자동 차감은 만료 시각·획득 시각·ID 순이다. 당일 낮에 획득한 지급분을 당일 사용 가능하게 기존 획득 시각 제약을 변경하고 승인 시각을 별도로 보존한다.
3. 변경 전 보상 획득 여부와 미지급 획득 자격을 확인한다. 당일 제외 후 해당 주 인정 일수가 6일 미만으로 내려가면 거부한다. 무료/보상 어느 지급분을 써도 동일하다. 보상 조회 전후와 기존 보상의 예약/사용/만료에 따라 결과가 달라지지 않아야 한다. 6일 이상 남으면 허용한다.
4. 보상 미획득·조건 미충족 상태에서는 당일 사용을 허용한다. 연차일은 이후 공부해도 보상 인정 일수에서 제외한다. 실제 시간·목표 달성 여부는 보존하고 타이머를 자동 종료하지 않는다. 휴무·미설정만으로 새 사용 제한을 추가하지 않는다.
5. 미래 예약만 사용일 06:00 전 취소/변경 가능하다. 오늘로 변경하면 즉시 사용 확정이며 취소/변경할 수 없다. 변경 시 기존 지급분을 유지하고 실패하면 원래 예약을 보존한다. 취소 시 만료일은 유지한다.
6. 사용자·날짜별 최대 1개, 서버 인증 UID, 트랜잭션, 기존 revision·요청 ID에 의한 동시 요청/중복 차감 방지를 유지한다. 잠금 대기 후 실제 판정 시점의 날짜·만료·보상 조건을 검증한다.

무료 연차의 월요일 지급·다음 월요일 만료 및 2026-11-02 지급 시작, 보상 연차의 6일 달성 즉시 지급·획득 주 시작+21일 만료는 유지한다. 무료 지급과 보상 획득을 혼동하지 않는다.

## 화면 변경

| 위치 | 적용 내용 |
| --- | --- |
| 연차 달력 | 오늘 선택·사용 허용. 과거는 내역 조회만 가능. 오늘 표시와 연차 비행기 표시 유지 |
| 날짜별 행동 | 오늘은 ‘오늘 연차 사용’, 미래는 ‘연차 예약’. USED는 취소/변경 버튼 없음 |
| 당일 확인창 | 공부 날짜와 종료 시각, 즉시 적용·취소/변경 불가 안내 |
| 미래 → 오늘 변경창 | 기존 날짜 → 오늘 표시. 즉시 사용 및 취소/변경 불가 안내 |
| 미래 예약 확인창 | 사용일 06:00부터 적용, 그 전까지 취소/변경 가능 안내 |
| 결과 문구 | 당일 ‘연차를 사용했어요’, 미래 ‘연차를 예약했어요’, 당일 변경은 ‘예약을 오늘로 변경하고 연차를 사용했어요’ |
| 연차 메인 | ‘오늘 연차 사용 중’을 ‘다가오는 연차’와 별도로 표시. 사용 가능 잔액에서 USED/SCHEDULED 제외 |
| 보상 진행도 | 실제 목표 달성과 보상 인정 일수 구분. 연차일 제외 사실 안내 |
| 기록·홈·친구 | 연차 출석 반영, 실제 공부 시간·목표 달성·진행 중 타이머 유지 |
| 도움말·시안 | 연차/프로필 이용 안내, 스토리북 문구와 상태를 함께 변경 |

당일 확인 문구: ‘오늘 공부 날짜에 바로 적용되며, 사용 후 취소하거나 날짜를 변경할 수 없어요.’ 날짜는 ‘10월 27일 공부 날짜 · 10월 28일 오전 6시까지’처럼 종료 시각과 함께 표시한다.

보상 보호 거부 문구: ‘오늘은 이번 주 보상 연차 획득에 포함된 날이라 연차로 변경할 수 없어요.’ 선택 상태에서는 불가 사유를 표시하고 서버도 동일하게 검증한다.

확인 중 06:00이 지나면 새 날짜로 자동 신청하지 않는다. 기존 확인을 무효화하고 날짜·상태를 갱신한 뒤 재확인받는다. 서버에서도 과거 날짜 요청을 거부한다. 통신 실패는 성공으로 표시하지 않고 같은 요청 재시도/조회로 확인한다. 승인 후 응답이 유실된 재시도는 날짜가 지나도 중복 사용하지 않는다. 성공 후 잔액·출석·보상 진행도를 함께 갱신한다.

## 완료 기준과 검증 사례

- 10월 28일 02:00에는 10월 27일 공부 날짜 사용 가능, 06:00부터 같은 날짜 신규 사용 불가.
- 당일 낮에 획득한 유효 지급분 사용 가능. 획득 전·만료 정각부터 사용 불가.
- 토요일 6번째 목표 달성 후 오늘 연차 사용 시 5일이 되므로 거부. 보상 조회 전/후, 무료/보상 지급분, 보상 예약/사용/만료 상태 모두 같은 결과.
- 일요일 7일 달성 후 오늘 제외 시 6일이 남으면 허용. 목표 달성 전 연차 사용한 날은 나중에 달성해도 보상 계산에서 제외.
- 미래 예약 → 오늘은 즉시 USED, 취소/변경 불가. 실패 시 기존 예약 유지. 미래 예약 취소/변경은 사용일 06:00 직전 가능, 정각부터 불가.
- 연차일의 공부 시간·목표 달성 보존, 출석은 leave 우선. 진행 중 타이머와 사용 후 공부 가능 여부 확인.
- 동일 날짜 동시 사용, 보상 조회와 사용 동시 요청, revision 충돌, 응답 유실 후 재시도, 잔액 부족, 타인 요청 검증.
- 기존 예약과 USED 이력 보존, 앱 복귀 및 확인창에서의 날짜 경계, 화면별 상태 갱신 확인.
- 린트·타입 검사와 관련 단위/실제 DB 트랜잭션 검증 후 구현 보고서를 남긴다. 정책 확정을 구현 완료로 기록하지 않는다.
