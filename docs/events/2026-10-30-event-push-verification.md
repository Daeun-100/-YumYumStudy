# 이벤트 스킨 지급 푸시 연동 검증

- 기록 ID: `2026-event-push-verification`
- 확인일: 2026-10-30 한국 시간.
- 상태: 서버 반영·무발송 검증 완료. 실제 기기 수신 미확인.
- 목적: 스킨 신규 지급이 확정된 사용자에게 이벤트당 고유 알림을 보낸다. 문구는 기본값·직접 지정·알림 끄기를 지원한다.

## 서버 반영

- 마이그레이션: `20261029154729_event_skin_notifications`.
- 테이블: `private.event_notifications`. 작업·사용자별 고유 알림 UUID, 고정 문구, 비동기 HTTP 요청 ID, 처리 상태를 저장한다.
- Edge Function: `event-notifications` v2. 기존 `admin-notifications` 발송 기능과 공유 서버에 이미 구성된 신뢰된 DB→Edge 자격을 재사용한다. 비밀값은 조회·출력·기록하지 않았다.
- 신규 클라이언트 배포·APK 생성·배경 변경·추가 이벤트 지급은 하지 않았다. 기존 알림 허용 및 등록 기기를 사용한다.

## 검증 결과

- 자동 테스트 377개, 린트·타입 검사 통과.
- 격리 DB: 기존 이벤트·스킨·원격 이미지 예약 기능 유지, 신규 지급자 알림, 기존 보유자 제외, 알림 끄기, 문구 검증, 동일 작업 중복 방지, Vault 미설정·HTTP 큐 오류의 지급 유지, 앱 역할의 큐·운영 RPC 접근 차단 확인. 격리 DB의 Vault·HTTP·Cron은 대체 구현이다.
- 실제 서버: 0번방에 테스트 스킨을 잠시 등록하고 한 트랜잭션에서 예약·지급했다. 새 보유 11건, 알림 큐 11건, HTTP 대기 11건과 지정 문구 일치를 확인했다. 트랜잭션 전체를 롤백했으므로 푸시는 실행되지 않았다. 이후 테스트 스킨·작업·보유·알림 큐 0건을 확인했다.
- 실제 DB→Edge 무발송 검증: HTTP 요청 31은 200과 `configured: true`, 잘못된 자격 요청 32는 401. 조회용 임의 UUID에는 알림을 만들거나 발송하지 않았다.
- 신규 공개 운영 RPC 3개는 SECURITY INVOKER이며 anon/authenticated 실행 권한이 없고 service_role만 호출한다.
- 보안 점검의 새 정보는 RLS가 적용된 private 알림 큐에 정책이 없는 구성 1건이다. 테이블 직접 접근을 차단하고 제한된 운영 함수만 사용한다. 기존 경고는 변경하지 않았다.

## 실제 운영 범위와 한계

- 기존 보유·실패·제외·배경 전환에는 알림을 보내지 않는다. 여러 신규 스킨은 사용자·작업당 한 알림으로 묶는다.
- 알림 큐와 기존 발송 함수는 같은 UUID를 사용한다. 재요청은 같은 ID로만 수행하고 신규 ID로 중복 발송하지 않는다.
- 큐의 completed는 발송 함수 처리 완료다. Expo/Web Push 접수나 실제 기기의 알림 표시는 각각 확인해야 한다. 기기 미등록·알림 거부·푸시 서비스 오류가 있어도 스킨 지급은 보존한다.
- 실제 기기 수신·알림 클릭 후 스킨 화면 이동은 검증하지 않았다. 현재는 기존 알림 표시 기능만 사용한다.
- 이 검증에서는 알림 서비스를 통해 사용자에게 실제 메시지를 보내지 않았다. 과거 지급 이력 자동 소급 발송도 없다.
