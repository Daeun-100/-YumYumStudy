# EAS OTA 업데이트 안내 토스트 명세

상태: Storybook 동작 시안, 실제 앱 연결 전

EAS OTA가 적용 가능한 상태임을 알리고 마이페이지의 기존 업데이트 버튼으로 안내한다. 토스트에서 업데이트를 적용하지 않는다. 기존 [공통 토스트](../development/TOASTS.md)의 표시 구조를 공유하고, 호출한 기능이 닫는 시점을 결정하는 외부 제어형을 추가하는 방향이다.

## 닫힘 정책

- 자동형은 기존처럼 지정 시간 경과 후 닫는다. 기존 목표 달성 4초·보상 안내 6초 정책을 유지한다.
- 외부 제어형은 자동 종료 타이머 없이 유지한다. 호출한 기능이 안내 인스턴스 ID로 닫기를 요청한다.
- 버튼 실행과 닫기는 분리한다. 클릭 즉시·작업 성공·특정 상태 충족 등 업무 조건은 호출한 기능에서 판단한다.
- X 표시 여부와 동작 버튼은 안내별로 지정한다. X를 숨기는 경우에도 실패 시 이용할 수 있는 유효한 종료 경로를 제공한다.
- 이미 닫힌 인스턴스의 늦은 완료 응답으로 새 안내를 닫지 않는다. 같은 논리적 안내의 중복 요청은 합친다.
- 외부 제어형은 화면 이동·시간 경과만으로 닫지 않는다. 백그라운드·키보드·대화상자 중에는 상태를 유지하고 표시 가능해지면 이어 표시하는 것을 목표로 한다. 사용자·방 전환과 로그아웃 시 이전 문맥의 안내를 정리한다.
- 앱 완전 종료·웹 새로고침 후 토스트나 대기열을 복원하지 않는다. 각 기능이 실제 상태를 다시 판정한다.

현재 공통 토스트의 백그라운드 정리 규칙과 외부 제어형의 유지 규칙을 구분하는 실제 호스트 변경은 후속 앱 연결 범위다. 이번 PR은 Storybook 시안과 명세다.

## 업데이트 안내 구성

- 제목: **업데이트가 준비됐어요**
- 본문과 별도 `얌얌스터디 업데이트` 보조 제목은 표시하지 않는다.
- 동작 버튼 하나: **바로가기 →**. 배경 없이 초록색 글자와 화살표를 사용한다.
- X는 이동 없이 안내를 닫는다.
- 카드 좌우 여백 16px, 위아래 여백 12px, 내부 간격 4px를 기준으로 한다. 닫기와 바로가기는 최소 44px 터치 영역을 유지한다.
- 이동 중에도 `바로가기 →` 모양을 유지한다. 로딩 아이콘이나 `이동하고 있어요` 문구를 표시하지 않는다. 연속 클릭으로 이동을 중복 실행하지 않는다.
- 토스트는 화면 조작을 막거나 배경을 어둡게 하지 않는다. 새 APK 버전·APK 다운로드 링크·OTA 수정 차수는 표시하지 않는다.

## 표시와 종료 조건

| 상태 | 동작 |
| --- | --- |
| 업데이트 확인 중·다운로드 중·새 OTA 없음 | 준비 완료 토스트를 표시하지 않음 |
| 현재 실행과 다른 호환 OTA가 다운로드되어 적용 대기 중 | 시간제한 없이 표시 |
| X 선택 | 해당 업데이트 ID의 안내를 이번 실행 동안 숨김 |
| 바로가기 선택 | 마이페이지의 업데이트 행으로 이동 요청, 아직 닫지 않음 |
| 목적지의 업데이트 행 표시 완료 | 해당 토스트 ID로 닫기 요청 |
| 이동 또는 목적지 표시 실패 | 유지, 오류와 재시도 제공 |
| 목적지에서 사용자가 적용하기 선택 | 기존 OTA 기능이 처리, 토스트와 분리 |

실제 표시 판정은 `expo-updates`의 적용 대기 상태와 다운로드된 업데이트 ID를 사용한다. X로 닫아도 다운로드된 OTA와 마이페이지 적용 기능은 유지한다. 재실행 시 실제 실행 업데이트와 적용 대기를 다시 확인하며, 이미 적용된 OTA를 다시 안내하지 않는다. iPhone 웹앱은 기존 웹 업데이트 경로를 따른다.

## 이동 목적지와 강조

마이페이지 `/(tabs)/profile`의 **이용 안내 → 앱 업데이트 → 적용하기** 행이 목적지다. `공부와 연차 이용 안내` 아래, `앱 정보` 위에 있는 기존 `OtaUpdateRowView`를 재사용한다. 앱 정보 화면으로 이동하거나 새 업데이트 카드를 추가하지 않는다.

레이아웃이 준비된 뒤 이용 안내 섹션까지 스크롤한다. 하단이므로 스크롤 가능한 최대 위치에서 멈출 수 있으며 적용하기 버튼이 화면 안에 보여야 한다. 이미 마이페이지에 있다면 같은 화면을 중복으로 쌓지 않는다. 실제 앱 연결 시 목적지 지정과 영역 표시 완료 신호를 함께 구현한다.

도착 후 **앱 업데이트 행의 배경만 한 번** 진해졌다가 돌아온다. 80ms 진입·100ms 유지·300ms 복귀로 전체 약 0.48초다. 반복하거나 버튼을 자동 실행하지 않는다. 동작 줄이기 설정에서는 1.2초간 정적인 강조 후 해제한다. 입력 포커스를 강제로 옮기지 않는다.

## Storybook과 검증 범위

`공통 컴포넌트/토스트 · EAS 업데이트`에서 기본·320px·이동 실패·실패 후 재시도·외부 조건 대기를 확인한다. 목적지는 기존 `ProfileUpdates` 전체 화면을 재사용하며, 업데이트 행까지 스크롤한 뒤 배경을 강조한다. 목적지의 적용하기 버튼은 기존 시안의 모의 동작이다.

이동 버튼 클릭과 목적지 표시 완료가 분리되고, 실패 시 유지·재시도가 가능하며, 도착 후에도 적용하기 버튼이 실행 전 상태인지 검증한다. 실제 EAS 접속·다운로드·앱 다시 시작과 프로덕션 라우팅은 이번 시안에서 실행하지 않는다. Android 실기기의 실제 업데이트·기록 보존·네이티브 화면 배치는 앱 연결 후 별도 검증한다.

기술 기준: [SDK 58 Expo Updates](https://docs.expo.dev/versions/v58.0.0/sdk/updates/), [EAS 업데이트 다운로드와 실행](https://docs.expo.dev/eas-update/download-updates/). 배포는 기존 master 호환성 검토와 릴리스 절차를 따른다.
