# 04 — 목표·기록 (병렬 D)

선행: 00 병합. 소유: GoalsScreen, HistoryScreen, goals/history 라우트, tests/goals-history. DB 함수는 01 소유다.

## 바로 진행 가능한 부분

- 월~일 0~1,440분 정수/미설정 입력과 조회를 만든다. getGoalSettings로 현재·예약 목표와 적용일을 구분하고 saveGoals로 저장한다. 저장 후 다음 공부 날짜 적용 안내와 재조회를 제공한다.
- 본인 기록을 날짜 범위로 조회하고 날짜별 종료 세션 합계와 목표 스냅샷을 표시한다. 최초 범위는 최근 7개 공부 날짜로 하며 이전/다음 범위를 조회할 수 있게 한다.
- present는 출석, pending은 아직 공부 기록 없음, absent는 종료된 날짜의 공부 없음으로 표시한다. isRestDay는 별도 휴무 표시다. 목표 미설정, 기록 없음, 네트워크 오류를 구분한다.
- 진행 중 세션은 종료 확정 합계에 섞지 않는다. 과거 날짜까지 지속된 세션의 표시 범위는 CONTRACT.md와 01의 보고서를 확인한다.

## 확정된 목표 저장 정책

0분=휴무, null=미설정, 상한 1,440분, 변경은 다음 공부 날짜 오전 6시부터다. 현재·과거 날짜의 목표는 바꾸지 않는다. 110 마이그레이션과 saveGoals/getGoalSettings 연결이 준비되어 있으므로 화면을 연결할 수 있다. 출석은 목표와 별개로 진행 중 시간을 포함해 1초 이상이며 day-status.ts로 화면 시계 기준 상태를 다시 계산할 수 있다.

## 검증 및 완료

- 월~일 순서, null과 0 구분, 미설정 목표, 빈 기록, 조회 실패, 6시 기준 날짜 범위를 검사한다.
- 정책 확정 후 저장 재조회·과거 스냅샷 보존을 확인한다. DB 구현 변경은 01 또는 통합 담당자에게 요청한다.
- 린트·타입 검사 및 `reports/04.md`. 화면과 API 통합 검증 결과를 구분해서 보고한다.
