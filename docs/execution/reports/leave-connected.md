# 연차 탭 UI 및 실제 기능 연결

## 구현

- LeaveView를 앱과 Storybook에서 공유한다. 샘플 데이터와 샘플 변경 동작은 stories/screens/LeaveLayout.tsx 안에만 둔다.
- 실제 잔여 연차, 가장 빠른 만료, 만료일별 개수, 다가오는 예약, 이번 주 목표 달성 일수를 표시한다.
- 달력의 휴무는 해당 날짜의 목표 스냅샷, 연차 표시는 실제 예약/사용 건을 사용한다.
- 신규 예약과 취소는 기존 mutate_leave 및 UID별 영속 요청 ID/버전 관리로 연결한다. 중복 탭을 막고, 응답 유실은 기존 요청으로 복구한다. 성공 응답의 잔액·예약 목록을 즉시 반영하고 공부 현황도 갱신한다.
- 현재 공부 날짜(KST 오전 6시 경계), 만료 정각, 이미 예약된 날짜, 잔액 부족을 검사한다.
- 네트워크 오류, 잔액 0, 로딩, 새로고침, 복구 요청 중 추가 변경 차단을 처리한다. 조회 실패를 주간 달성 0일로 표시하지 않는다.

## 날짜 변경 서버 수정 — 적용 완료

280_leave_reschedule.sql은 기존 schedule_leave가 AVAILABLE 외에 아직 시작하지 않은 SCHEDULED 지급 건의 날짜 변경도 허용하도록 수정한다. 기존 mutate_leave의 프로필 잠금/리비전/재시도 규칙을 그대로 사용한다. 단일 UPDATE이므로 충돌·만료·날짜 오류 시 기존 예약이 유지된다. 직접 schedule_leave 실행 권한은 계속 차단한다.

원격 함수 정의를 읽어 로컬 기반과 일치함을 확인했다. 최초 자동 승인 검토에서 운영 DB 변경이 차단되었고, 사용자가 적용 범위를 확인한 뒤 명시적으로 승인했다. 승인 후 운영 Supabase SQL Editor에서 280을 적용했으며 Success를 확인했다. 기존 마이그레이션과 마찬가지로 CLI migration history에는 등록하지 않았다.

supabase/tests/leave_reschedule.sql에 예약 이동, 재전송, 오래된 버전, 날짜 중복, 만료/당일 예약 차단, 실패 시 원래 예약 유지, 직접 RPC 우회 차단을 검증하는 롤백 테스트를 준비했다. 원격 authenticated 역할 롤백 테스트를 실행해 통과했다. 구형 테스트 계정이 입장 절차 도입 전에 생성되어, 테스트 트랜잭션에서만 입장 완료 상태를 보완했다. 검사 후 계정·지급 건·예약·요청 정보의 모든 테스트 변경은 ROLLBACK했다.

## 검증

- 단위 테스트 56개 통과: 만료 정각 제외, 공부 날짜, 예약 중복/변경 가능 여부, 연차·휴무·미설정 제외 및 진행 중 공부 포함.
- Expo lint, TypeScript noEmit, 웹 export, Storybook build 통과.
- 브라우저 실제 테스트 방: 서버에서 잔액 0, 주간 달성 0을 조회하고 달력 전환 및 잔액 부족 예약 차단을 확인했다. 실제 예약/취소를 할 수 있는 지급 건이 없어 원격 변경 E2E는 수행하지 않았다.
- 공통 화면의 Storybook 샘플: 10/29→10/30 변경, 취소 후 사용 가능 복원, 재예약 후 달력/사용 예정 표시를 확인했다. 이는 샘플 동작 검증이다.
