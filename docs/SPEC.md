# 제품 명세 v0.5

작성일: 2026-10-26. 정책 개정: 2026-10-27(당일 연차 사용). 이 문서는 구현 전 명세이며 구현 완료를 의미하지 않는다.

## 목적과 확정된 방향

4명의 스터디 구성원이 요일별 공부 목표를 설정하고 타이머로 공부를 기록하며 서로의 현황을 확인한다. 출석과 연차를 함께 관리한다. 운영과 설치 부담을 줄인다.

| 구분 | 결정 |
| --- | --- |
| Android | APK 직접 배포 |
| iPhone | Safari 웹앱, 홈 화면 추가 지원 예정 |
| 코드 | Expo + React Native + TypeScript 공통 코드 |
| 백엔드 | Supabase Cloud, PostgreSQL/Auth/Realtime |
| 방 | 작성자가 포함된 고정 스터디방 하나에 자동 참여. 방 생성·검색·선택 없음 |
| 회원 구분 | 로그인 화면 없이 자동 익명 인증으로 UID 발급. 이름은 표시용 |
| 공부 날짜 | Asia/Seoul 오전 6시부터 다음 날 오전 6시 전까지를 하루로 계산 |
| 타이머 유지 | 화면 이탈·잠금·앱 종료·연결 단절에도 세션 유지. 직접 중지하면 종료 |

오전 6시 기준과 출석·연차 기능은 이전 논의에서 이어온 요구사항이다. 세부 정책은 DECISIONS.md에서 별도로 확정한다.

## 플랫폼 범위

| 기능 | Android 앱 | iPhone 웹앱 |
| --- | --- | --- |
| 자동 UID, 목표, 타이머, 공유 | 지원 예정 | 지원 예정 |
| 출석·연차 | 동일한 서버 규칙 | 동일한 서버 규칙 |
| 화면 이탈·잠금 중 시간 누적 | 지원 예정 | 지원 예정 |
| 허용 앱 구별 | 후속 실기기 검증 | 지원하지 않음 |
| 다른 앱 차단 | 후속 기술 검증, MVP 제외 | 지원하지 않음 |

MVP에서는 두 플랫폼 모두 사용자가 중지할 때까지 경과 시간을 누적한다. 다른 앱 사용 시간도 포함되며 실제 공부 여부를 판별하지 않는다. Android 허용 앱·차단은 구현 가능성을 검증한 후 별도 범위로 추가한다.

## 화면과 사용자 흐름

1. 첫 실행: 저장된 익명 세션이 없으면 UID를 자동 발급하고 고정 방에 자동 참여한다. 로그인·회원가입·방 선택 화면은 없다. 표시 이름은 기록 식별 키로 사용하지 않는다.
2. 오늘: 오늘의 공부 날짜, 목표, 누적 시간, 시작/중지 버튼, 저장 상태를 표시한다.
3. 친구들: 구성원 4명의 누적 시간, 목표, 타이머 진행 중/휴식 상태를 표시한다. 연결 상태와 최종 갱신 시각은 별도로 표시하며 실제 공부 여부를 보증하지 않는다.
4. 목표 설정: 월~일 각각 목표 시간을 분 단위로 설정한다.
5. 기록: 주간·월간 공부 현황과 선택 날짜의 세션 합계·목표·출석 결과를 표시한다. 세션별 시작·종료 시각과 공부 시간은 목록에서 확인하며 별도 세션 상세 화면이나 상세 이동은 제공하지 않는다. 친구 기록에도 같은 구성을 사용한다.
6. 연차: 사용 가능 수량, 지급·사용·만료 내역과 날짜별 사용 상태를 표시한다. 오늘은 즉시 사용, 미래는 예약으로 구분한다. 오늘 사용 중 상태와 다가오는 예약을 따로 보여주며 당일 확정 전 취소·변경 불가를 안내한다.

## 타이머 및 동기화 요구사항

- 시작·종료 시각을 저장하고 차이로 시간을 계산한다. 화면의 초 단위 증가 횟수를 기록값으로 사용하지 않는다.
- 사용자별 진행 중 세션은 최대 하나다. 두 기기/탭에서 동시에 시작해도 서버가 하나만 허용한다.
- 시작은 서버 승인 후 성공 처리한다. MVP에서 오프라인 시작은 허용하지 않는다.
- 중지 요청은 재전송해도 중복 기록을 만들지 않는다. 통신 실패 시 미저장 상태와 재시도를 보여준다.
- 화면 숨김·잠금·앱 비활성 전환 시 세션을 중지하지 않는다. 백그라운드에서 매초 코드가 실행되거나 통신이 유지될 필요가 없다.
- 서버에 저장된 시작 시각과 현재 시각의 차이로 진행 중 시간을 계산한다. 앱 강제 종료·네트워크 단절 후에도 세션은 유지되고 복귀 시 서버 기록으로 복원한다.
- heartbeat는 연결 상태 표시용이며 누락을 세션 종료나 시간 차감 근거로 사용하지 않는다.
- 중지 요청이 실패하면 종료 확정 전임을 표시하고 재시도를 제공한다. MVP에서는 서버가 중지를 승인한 시각에 종료한다. 요청 실패부터 승인까지의 시간도 포함되며 사용자가 이를 알 수 있게 안내한다.
- 사용자가 중지를 잊으면 시간이 계속 누적된다. 최대 세션 시간·복귀 확인·기록 수정 정책은 미정이며 확정 전 자동 종료를 추가하지 않는다.
- 오전 6시를 넘는 세션은 날짜 경계에서 나누어 합산한다. 서버 시각을 기준으로 하고 클라이언트 시각 조작을 신뢰하지 않는다.
- 친구 화면의 진행 중 시간도 서버의 시작 시각으로 계산한다. 오래된 heartbeat는 연결 확인이 오래되었음을 표시하되 타이머를 휴식으로 바꾸지 않는다. 진행 중 합계와 종료 후 확정 합계를 구분한다.

## 목표·출석·연차 요구사항

- 무료 연차는 보상 연차와 별도로 매주 월요일 한국시간 06:00에 1개 지급하고, 다음 월요일 06:00 정각 소멸한다. 이월되지 않는다.
- 무료 자동 지급은 2026-11-02 06:00부터 시작한다. 2026-10-26 주간분은 사용자가 별도로 지시하기 전까지 지급하지 않는다.
- 아래의 6일 달성 및 21일 만료 규칙은 보상 연차에 해당한다. 중복 지급 방지는 사용자+획득 주+종류(free/reward) 기준이다.

- 목표는 요일별 0~1,440분 정수로 관리한다. 0분은 휴무이며 null(미설정)과 구분한다.
- 미설정은 아직 목표를 정하지 않은 초기 상태다. 요일 편집창은 즉시 시간 휠을 보여주고 공부 시간 또는 휴무를 선택한다. 설정한 목표를 미설정으로 되돌리는 UI는 제공하지 않는다.
- 최초 목표 저장은 서버 기준 현재 공부 날짜부터 즉시 적용하고 이미 공부한 시간도 포함한다. 기존 목표 이력이 있는 계정의 목표 변경은 서버 시각 기준 다음 공부 날짜 오전 6시부터 적용하고 현재·과거 목표 이력을 보존한다. 예를 들어 10월 26일 오전 2시에 변경하면 현재 공부 날짜는 10월 25일이며, 10월 26일 오전 6시부터 새 목표가 적용된다.
- 출석은 진행 중 시간을 포함해 해당 공부 날짜에 기록된 정수 초 합계가 1초 이상이면 present이며 목표 달성과 별개다. 목표 미달이어도 출석한다.
- 0초인 현재·미래 공부 날짜는 pending, 다음 오전 6시가 지나 종료된 공부 날짜는 absent로 표시한다. 휴무 여부(isRestDay)는 별도로 유지하므로 휴무일 공부도 출석으로 남긴다. absent는 공부 없음 표시이며 휴무일 불이익을 뜻하지 않는다.
- goalAchieved는 양수 목표에 대해서만 계산한다. 0분 휴무와 미설정은 null로 반환하고 자동 달성이나 0으로 나누는 달성률을 만들지 않는다.
- 현재 목표와 다음 공부 날짜의 예약 목표를 구분해 조회한다. 같은 적용일의 예약 목표를 반복 저장하면 하나의 버전을 갱신한다. 현재·과거 버전은 변경하지 않는다.
- 연차는 지급 건마다 수량과 만료 시각을 보존한다. 만료된 지급분은 사용할 수 없다.
- 보상 연차 획득은 월~일 중 6일 목표 달성 시 주당 1개이며 최초 지급은 없다. 주간 범위는 월요일 오전 6시부터 다음 월요일 오전 6시 전까지다. 6번째 날 목표 달성 즉시 지급하며 바로 사용할 수 있다. 당일 사용은 아래 보상 보호 조건을 따른다. UID+획득 주+종류에 고유 제약을 두어 재조회·동시 요청·7번째 달성에 중복 지급하지 않는다.
- 만료는 획득 주의 다음 주 월요일 오전 6시부터 2주 뒤다. 즉 획득 주 월요일 오전 6시 + 21일이며, 만료 시각 정각부터 사용할 수 없다. 예: 2026-10-26~2026-11-01 공부 주간에 획득한 연차는 2026-11-16 오전 6시 만료다. 같은 획득 주는 지급 요일과 무관하게 같은 만료 시각을 갖는다.
- 연차 차감은 서버 트랜잭션에서 처리한다. 중복 사용과 잔액 음수를 막는다.
- 진행 중인 공부도 연차 목표 달성에 포함한다. 목표가 양수인 서로 다른 공부 날짜 6일이 필요하며 휴무(0분)·미설정은 제외한다. getLeaveStatus 조회 시 누락된 지급을 기록하고, earnedAt은 실제 6번째 달성 시각으로 계산한다. 앱 미실행 중 과거 획득분도 같은 주·같은 만료로 복구한다. 시각 경과만으로 DB INSERT가 실행되는 구조나 백그라운드 지급 알림은 포함하지 않는다.
- 당일 사용 정책은 2026-10-27 확정하고 앱 소스·DB 구현을 완료했다. 앱 배포는 별도다. 현재 공부 날짜는 서버 승인 즉시 사용 완료, 미래 날짜는 예약이며 과거 날짜는 사용할 수 없다. 당일 사용은 해당 공부 날짜 전체에 적용하고 승인 시각은 별도로 보존한다.
- 미래 예약만 사용일 한국시간 06:00 전까지 취소/변경할 수 있다. 오늘로 변경하면 즉시 사용 완료이며 이후 취소/변경 불가다. 변경 실패 시 기존 예약을 유지한다. 취소 시 원래 만료일을 유지한다.
- 요청 승인 시점에 획득했고 미만료인 연차만 사용한다. 미래 예약은 사용일 시작 시각도 만료 전이어야 한다. 자동 선택은 만료 시각, 획득 시각, ID 순이며 날짜 변경은 기존 지급분을 유지한다.
- 사용자당 공부 날짜별 연차는 1개다. 연차 출석은 실제 공부 출석보다 우선하지만 실제 시간과 goalAchieved는 보존한다. 타이머를 자동 종료하지 않으며 연차 사용 후에도 공부할 수 있다. 미래 예약은 미리 출석 처리하지 않는다.
- 보상 인정 일수는 양수 목표 달성일 중 연차 사용일을 제외한 수다. 당일 제외 후 6일 미만이고 변경 전 해당 주 보상을 이미 획득했거나 획득 조건을 충족했다면 사용하는 연차 종류와 관계없이 당일 사용을 거부한다. 보상 조회 전이거나 기존 보상을 예약/사용/만료했더라도 같은 결과여야 한다. 당일 제외 후에도 6일 이상이면 허용하며 이미 획득한 보상을 회수하지 않는다.
- 보상 미획득·조건 미충족 상태에서는 당일 사용을 허용하되 그 날짜는 이후 목표를 달성해도 보상 인정 일수에서 제외한다. 휴무·미설정 여부만으로 새 사용 제한을 추가하지 않는다.
- 확인창에서 공부 날짜가 바뀌면 날짜와 상태를 갱신하고 다시 확인받는다. 성공 후 잔액·출석·보상 진행도를 함께 갱신한다. 화면 문구와 경계 검증은 `execution/05-attendance-leave.md`를 따른다.
- 만료 조회에는 별도 상시 서버가 필요 없지만 정기 지급·일별 정산에는 서버 작업 또는 지연 계산이 필요하다.

## 접근 권한

- 설치 또는 웹 접속 후 익명 인증을 자동 수행한다. 저장된 인증 세션을 재사용하며 UID만으로 타인 인증을 대신할 수 없다.
- 스터디방은 하나이며 구성원은 방의 공부 현황을 조회한다. 방 생성·초대·가입 승인·다른 그룹 분리는 MVP에 없다.
- 본인 목표와 세션에만 변경 권한을 갖는다. 타인 기록과 연차 잔액을 직접 변경할 수 없다.
- 연차 지급, 최종 시간 정산, 출석 확정은 서버에서 수행한다.
- API에 공개하는 모든 테이블에 RLS(행 단위 접근 권한)를 적용한다. 인증 세션 없는 요청과 타인 기록 변경을 거부하고, 자동 익명 인증된 사용자의 방 현황 조회는 허용하는지 검증한다.
- 사용자 ID는 서버 인증 세션의 UID로 확인한다. 요청에 담긴 UID나 표시 이름을 그대로 신뢰하지 않는다.
- MVP에 로그아웃 UI는 없다. 앱 데이터·브라우저 저장소 삭제 또는 다른 기기 사용 시 새 UID가 생성될 수 있다. 이름이 같아도 기존 기록과 자동 병합하지 않는다. UID는 사람이나 영구적인 기기 식별자가 아니다.
- 예상 사용자는 4명이지만 신규 UID를 기존 4명으로 자동 판별하거나 가입을 4명으로 제한하지 않는다. 고정 방 자동 참여는 비공개 초대 인증을 보장하지 않는다.

## MVP 완료 기준

- Android 실기기에 APK 설치, iPhone Safari 및 홈 화면 실행을 확인한다.
- 로그인·방 생성 없이 UID를 발급받아 같은 방에 진입하고, 일반 재실행·새로고침에서는 저장된 세션과 UID를 재사용한다.
- 서로 다른 4개 UID의 목표·세션·일별 합계가 서로 맞고, 이름 중복·변경으로 기록 소유자가 바뀌지 않는다.
- 인증 없는 DB 요청 및 다른 UID의 기록 변경은 거부된다. 저장소 초기화 시 새 UID로 처리하고 이전 기록을 자동 인계하지 않는다.
- 중복 시작·중복 종료·6시 경계·이탈·강제 종료·통신 실패 후 복귀를 검증한다.
- 화면 이탈·잠금·앱 종료·연결 단절 후에도 시간이 누적되고 복귀 시 복원된다. 중지 실패·재시도·승인 시각 기준 종료를 검증한다.
- 출석·연차 정책 확정 후 지급/차감/취소/만료 경계와 권한을 검증한다.
- iPhone의 앱 구별·차단 미지원과 저장 실패 상태를 화면에서 명확히 안내한다.

## 버전 및 업데이트 안내

- 작성자가 새 APK/웹을 배포한 후 Supabase의 플랫폼별 배포 정보를 활성화하면 새 버전 안내를 표시한다.
- 실행·복귀 시 확인하고 사용 중 주기적으로 확인하지 않는다. 확인 실패 시 수동 재시도를 제공한다. Android는 다운로드 링크, 웹은 새로고침 버튼을 제공한다.
- 표시 버전과 단조 증가하는 배포 번호를 관리하고 더 높은 배포 번호만 안내한다. 안내를 나중으로 미룰 수 있다.
- 꺼진 앱에 OS 푸시 알림을 보내거나 자동 설치하지 않는다. 운영 절차는 RELEASES.md를 따른다.

## 제외 범위 (상세)

로그인·회원가입 화면, 이메일/비밀번호·소셜 로그인, 방 생성·검색·선택·초대·가입 승인, 다중 방, 기기 간 UID 이전·계정 복구, 스토어 공개, iOS 네이티브 배포, 결제, 채팅, 공개 가입 커뮤니티, 부정행위 완전 방지, 오프라인 공부 기록, Android 앱 차단은 첫 버전에 포함하지 않는다.
