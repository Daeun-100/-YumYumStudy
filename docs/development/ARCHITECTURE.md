# 기술 설계와 구현 원칙

제품 방향은 [제품 명세](../product/SPEC.md), 기능별 규칙은 [상세 기능 정책](../product/FEATURE-POLICIES.md), 데이터 인터페이스는 [공통 계약](CONTRACT.md)을 따른다. 서버 배포·복구는 [서버 운영](../operations/SERVER-OPERATIONS.md)을 참고한다.

## 구현 원칙과 구조

- 현재 소규모 스터디에 필요한 최소 구조와 의존성을 사용한다. 미래 확장을 위한 범용 방·권한·플러그인 계층을 미리 만들지 않는다.
- Expo 공통 코드와 Supabase Auth/PostgreSQL RPC·Realtime을 사용한다. 별도 API·WebSocket 서버를 만들지 않는다. 알림과 로그 감시는 Edge Function에서 처리한다.
- `src/app/`은 Expo Router 화면 연결, `src/features/`는 기능 화면·상태, `src/data/`는 서버 요청·응답 검증, `src/lib/`는 공통 타입·날짜·시계·저장 로직을 관리한다. 실제 중복이나 복잡함이 생길 때 분리한다.
- 앱과 Storybook은 공통 View를 사용한다. 샘플 상태·가짜 변경 동작은 Storybook 안에 두며 서버 실패를 샘플 데이터로 숨기지 않는다.
- 인증 세션과 기억한 UID를 구분한다. 저장된 UID가 있는데 인증을 복원하지 못하거나 UID가 다르면 새 사용자로 자동 대체하지 않는다. 초기 익명 가입 응답 자체가 유실된 경우에는 서버 생성 여부를 확인하지 못할 수 있다. 기기 변경·저장소 삭제 후 이전 계정 복구는 제공하지 않는다.
- 실제 방은 초대 코드·프로필 설정을 거쳐 입장한다. 테스트 방과 실제 방의 인증·저장 범위를 분리하고 사용자용 방 생성은 제공하지 않는다. 상세 방 전환 규칙은 기능 정책을 따른다.

## 데이터와 시간 계산

| 데이터 | 역할 |
| --- | --- |
| `profiles`, `study_room` | 인증 UID별 프로필, 입장·캐릭터·스킨과 고정 방 |
| `goal_versions` | 적용 공부 날짜별 요일 목표. 최초는 오늘, 이후 변경은 다음 공부 날짜 |
| `study_sessions`, `study_start_requests` | 원본 세션과 UID·요청 ID별 원래 세션 매핑 |
| `leave_grants`, `leave_requests` | 무료·보상·관리자 연차와 멱등 변경 요청 |
| `app_releases` | 플랫폼별 활성 배포와 업데이트 안내 |
| 스킨·포스트잇·알림 데이터 | 각 기능의 마이그레이션·서버 코드에서 구조와 접근 권한 관리 |

일별 합계는 원본 세션에서 조회하며 별도 일별 합계 테이블은 만들지 않는다. 공부 날짜는 서버에서 `(timestamp AT TIME ZONE 'Asia/Seoul' - interval '6 hours')::date`로 계산한다. 날짜 경계를 넘는 세션은 구간을 나누고 정수 초를 합산한다. 세션이 없는 LEFT JOIN 행을 진행 중 시간으로 집계하지 않는다.

종료 세션의 `closedSeconds`와 미종료 세션의 `runningSeconds`를 구분한다. 오늘·친구 화면에서 `activeSession`과 날짜 구간의 겹침으로 시간을 계산했다면 `runningSeconds`를 다시 더하지 않는다. 화면 시계는 서버 기준점과 monotonic 경과를 사용하고 재조회 시 기준을 갱신한다. 기기 벽시계 변경으로 확정 기록을 바꾸지 않는다.

출석·목표·연차 상태는 서로 다른 값이다. 당시 목표 버전과 실제 공부 시간을 보존한다. 지급 조회가 실제 획득보다 늦어도 보상의 `earnedAt`은 여섯 번째 달성 시각이고 `recorded_at`은 실제 처리 시각이다. 무료 지급은 cron과 조회 보충을 사용한다.

## 시작·중지와 Android 복구

- 진행 세션은 사용자별 부분 UNIQUE 제약으로 하나만 허용한다. 시작·종료·연차 변경은 서버 트랜잭션과 프로필 잠금으로 직렬화한다. 잠금 후의 시각으로 날짜·만료를 판정한다.
- 시작 요청 ID는 네트워크 전송 전에 UID별로 영속 저장한다. 저장 실패·손상·응답 유실·정리 실패 시 새 ID로 대체하지 않는다. 같은 요청은 종료된 원래 세션도 반환할 수 있으므로 복구 후 `getToday()`로 현재 상태를 조회한다. 미완료 요청이 없는 실행은 새 공부를 시작하지 않는다.
- 기본 타이머는 이탈·잠금·프로세스 종료·단절 후에도 서버 세션을 유지한다. 기본 모드 여부를 방·사용자별로 서버 시작 전에 저장해 복구 시 Android 감시 유실로 오인하지 않는다. 직접 중지는 최초 서버 승인 시각을 보존한다.
- Android 허용앱 모드는 명시적 시작에서 감시 준비 → 서버 승인 → 사용자·방·세션 바인딩 순서를 지킨다. 앱 내부 실행은 대상 패키지의 짧은 실행 허가를 만든다. 다른 앱으로 바로 전환하거나 잠금·권한 상실·감시 공백을 감지하면 중지하며 복귀 후 자동 재개하지 않는다.
- `StudyLink`는 바인딩과 최초 이탈 outbox를 먼저 보관한다. 이탈 시각은 서버 기준점과 Android monotonic 경과로 계산한다. 인증 정보는 메모리에만 두며 preferences·로그에 저장하지 않는다. JS가 멈춘 동안 네이티브 서비스가 인증된 종료 RPC를 보내고 만료·오프라인 실패는 복귀 시 정합화한다.
- `stop_study_on_exit`는 본인·입장·방·세션을 검증하고 시작 전·미래 시각을 보정하며 기존 종료 시각을 늘리지 않는다. 서버를 기다리기 전 저장된 이탈을 마지막 스냅샷에 반영해 이미 더한 시간을 제거한다. 미확인 중지가 있으면 새 시작을 막고, 이전 세션의 늦은 승인으로 새 감시 준비를 취소하지 않는다.
- 프로세스 재시작 시 발견한 감시 세션을 자동으로 다시 켜지 않는다. 서버 시작 후 바인딩 전에 프로세스가 종료된 세션은 재발견 시 보수적으로 정리한다. 연속 서버 lease 강제는 구현하지 않았다.
- 사용 이벤트는 관찰 기반이다. 최근 앱 전환, 시스템 UI, 분할 화면·PiP·제조사 절전은 실기기로 확인한다. 오프라인·강제 종료 중 친구에게 진행 중으로 보일 수 있으며 동기화 전에는 서버 종료를 보장하지 않는다.

## 조회·초기 진입·캐시

- 같은 데이터의 동시 조회는 진행 중 Promise를 공유한다. 조회 중 변경 이벤트가 오면 후속 조회를 예약한다. 시작·중지·사용자·방 변경은 세대를 바꿔 이전 응답이 최신 상태를 덮지 못하게 한다.
- 내 초기 복구·실시간 스냅샷과 친구 조회는 독립시킨다. 친구 지연·실패가 내 준비 완료를 막지 않게 하고, 시작·중지 승인 후 전체 조회가 버튼 완료를 붙잡지 않게 한다. Android 감시 준비·바인딩 순서는 생략하지 않는다.
- 숨김 화면의 모든 이미지 선로딩을 첫 진입 완료 조건으로 삼지 않는다. 내 상태가 준비된 뒤 화면을 공개한다. 로딩 중 입력·접근성, 오류·재시도, 이미지 표시의 실제 기기 동작은 별도로 검증한다.
- Realtime은 같은 방의 `profiles`·`study_sessions` 변경을 알리고 최종 데이터는 다시 조회한다. 소켓 접속과 Postgres 변경 수신 준비를 구분하며, 구성원별 온라인 Presence로 설명하지 않는다.
- 포스트잇은 비공개 `postits:room:<id>` Broadcast의 전체 행을 반영한다. 재연결·복귀 시 서버를 재조회하고 조회 중 이벤트를 재적용한다. 삭제 tombstone이 늦은 create·조회 응답으로 되살아나지 않게 한다. 오래된 공부 날짜의 포스트잇은 보관하되 숨긴다.
- 내 기간별 기록 요약의 영구 캐시는 프로젝트·사용자·방·범위로 분리하며 최대 24범위·7일 제한이다. 손상·중복 날짜·범위 이탈·이전 스키마는 복원하지 않는다. 캐시 읽기와 서버 조회를 병행하되 늦은 캐시가 서버 응답을 덮지 못하게 하고 캐시 표시 중임을 안내한다.
- 캐시는 시간 진행·새 시작의 근거가 아니다. 타이머 상태·시작 요청·친구 기록·상세 세션을 요약 캐시에 넣지 않는다. 상세 세션은 별도로 조회하며 서버의 1회 조회 최대 366일 제한과 UI의 과거 기간 이동을 구분한다. 상세 조회는 500개 단위 페이지와 요청 제한시간을 사용한다.
- 변경 가능한 조회 정책과 후속 설계는 [공부방 데이터 갱신 문서](../proposals/STUDY-REFRESH-DESIGN.md)의 상태와 실제 코드를 함께 확인한다. 과거 고정 주기를 새 정책으로 복원하지 않는다.
- Service Worker는 iPhone Web Push에 사용한다. 앱 화면·API·인증 응답은 캐시하지 않고 서버 승인 없는 신규 공부 기록도 허용하지 않는다.

## 성능 측정과 지연 진단

`src/lib/performance.ts`는 최근 200개 표본을 기기 메모리에만 보관한다. `getTimingSamples()`는 복사본을 반환하며 사용자 ID·토큰·요청 인자·오류 본문은 기록하지 않는다. 빌드 환경에 `EXPO_PUBLIC_PERFORMANCE_LOGS=true`를 설정하면 `[study-performance]` 로그를 출력한다. 이미 만든 번들에는 소급 적용되지 않는다.

| 표본 | 확인할 구간 |
| --- | --- |
| `identity.verify`, `identity.session` | 서버 인증 확인과 검증된 사용자·현재 세션 비교 |
| `startup.admission`, `startup.profile`, `startup.recover`, `startup.study` | 입장·프로필·이전 시작 복구·초기 조회 |
| `startup.visible` | StartupBoundary 마운트 후 화면 공개까지. OS 앱 실행 전체 시간은 아님 |
| `rpc.*`, `study.reconcile`, `study.refresh` | 개별 요청·기기 정합화·스냅샷 갱신 |
| `timer.status/transport/prepare/bind/toggle` | 기기 설정·감시 준비·바인딩·버튼 처리. toggle에는 후속 전체 조회 제외 |
| `postit.*`, `call-friend.*` | 포스트잇과 알림 함수의 개별 동작 |

같은 기기·네트워크에서 완전 종료 후 실행, 재실행, 시작·중지를 반복하고 중앙값과 느린 실행을 비교한다. 기본 모드·허용앱 모드, 정상 연결·오프라인 복구도 나눈다. 병행 요청 시간을 합산하지 않는다. DB 누적 통계나 API 게이트웨이 시간은 기기 네트워크·인증 잠금·감시·이미지 로딩을 포함하지 않으며 체감 지연이나 개선율의 대체 지표가 아니다.

알림 등록 폭주는 네이티브 토큰 이벤트의 재귀 등록 여부를 확인하고 서버 register·Auth·429 수와 기기 표본을 함께 비교한다. 한 결함이 모든 시간 초과의 유일한 원인이라고 단정하지 않는다. 실제 알림 발송은 자동 성능 진단에 넣지 않는다.

## 검증

린트·타입 검사와 날짜 경계·권한·동시 요청·응답 유실처럼 영향이 큰 자동 검사를 사용한다. DB 재현 SQL은 `supabase/tests/`에 있으며 외부 서비스 검사와 일반 테스트를 구분한다. 과거 테스트 개수·APK 해시·로컬 스크린샷은 현재 소스와 실제 배포·실기기 검증의 증거로 재사용하지 않는다.

기본 타이머 복구, Android 이탈·강제 종료·중지 재전송, 두 기기의 알림·스킨 전파와 iPhone 홈 화면·키보드는 배포 대상 버전에서 별도로 확인한다. iPhone 재현 절차는 [웹앱 테스트](IPHONE-WEB-TESTING.md), 기능별 기대 결과는 [기능 검증 기준](../product/FEATURE-POLICIES.md#기능-검증-기준)을 따른다.
