# 이벤트 기록과 예약 운영 명세

작성일: 2026년 10월 29일
상태: 예약·서버 이미지 구조 반영 및 실제 업로드·권한 검증 완료 / 앱 배포 대기

현재 구현·서버 반영 현황은 [이벤트 운영](../operations/EVENT-OPERATIONS.md)과 [서버 이미지 운영](../operations/ARTWORK-OPERATIONS.md)을 따른다. 코드 구현 완료와 공유 서버 반영·앱 배포는 구분한다.
운영 인터페이스: 관리자와 GPT의 프로젝트 채팅

관리자가 채팅으로 이벤트를 기록하고, 준비된 선물 지급과 홈·집중 화면의 이벤트 배경 변경을 예약한다. 기획·이미지·운영 결과는 `docs/events/`에 남기고, 실행 예약과 실제 지급·배경 운영 이력은 서버에 저장한다. 별도 관리자 화면은 만들지 않는다.

## 1. 현재 상태와 이번 범위

현재 스킨·배경 이미지는 앱 에셋이며, 이벤트 예약 서버는 반영·검증됐다. 배경 선택 앱 코드는 작업 브랜치에 있으나 앱 배포는 하지 않았다. 이번 후속 작업에서 **배경·스킨 이미지를 서버 저장소에서 전달하고, 앱에 준비된 효과를 서버 설정으로 조합**하도록 전환한다. 기존 지급·보유·착용·예약 정책은 유지한다. 아래 ‘이번 범위’에는 이 후속 전환을 포함하며, 현재 지원 여부는 운영 문서를 확인한다.

| 이번에 구현 | 이후 기능 개발 시 추가 |
| --- | --- |
| 이벤트 문서와 서버 이벤트 ID 연결 | 사용자용 이벤트 목록·상세 화면 |
| 특정 날짜·시각의 일회성 지급 예약 | 기간 내 접속·공부 조건에 따른 보상 |
| 서버 이미지로 등록한 스킨의 묶음 지급 | 배경·소품·효과 아이템의 개인 보유·적용·지급 |
| 홈·집중 배경 및 스킨 이미지 업로드·등록·조회·캐시 | 사용자 직접 이미지 업로드 |
| 기존 효과 종류의 선택과 검증된 매개변수 설정 | 새로운 효과 동작과 범용 효과 편집기 |
| 방별 홈·집중 배경의 기간 지정 변경과 기본 배경 복귀 | 사용자 개인별 보유 배경 선택 |
| 예약 조회·변경·취소, 실행 결과 조회·재실행 | 사탕 수집, 교환, 활동 진행 상황 |
| 중복 방지, 실행·지급 이력 | 배너 노출, 스킨과 독립된 화면 전체 효과의 시작·종료 자동화 |
| 운영용 서버 함수·스크립트와 채팅용 스킬 | 별도의 자동 실패 알림·재시도 정책 |

문서는 처음부터 모든 종류의 이벤트를 기록할 수 있다. 이번 자동 실행은 `grant_skins`와 `set_backgrounds`(홈·집중 공통 배경의 기간 지정 변경)를 지원한다. 배경 변경은 방에 적용하는 연출이며 개인 보유 아이템 지급은 후속 범위다. 미지원 구성은 문서에 기록하되 실행 예약은 거부하고 필요한 기능을 안내한다. 지원되지 않는 보상이 섞인 묶음은 일부만 몰래 예약하지 않는다.

전환 기능을 최초 한 번 앱 업데이트로 전달하고 적용한 사용자부터 서버 이미지를 지원한다. 이후 지원 규격의 새 배경·스킨 이미지와 기존 효과 설정 추가는 업로드·등록·예약만으로 운영한다. 새 효과 동작·캐릭터 종류·지원하지 않는 콘텐츠 스키마를 추가하면 코드 업데이트가 필요하다. 이미지 생성·실제 업로드·서버 변경·앱 배포는 이번 명세 개정 요청에 포함되지 않는다.

## 2. 저장 위치와 기준

| 위치 | 저장 내용 |
| --- | --- |
| `docs/events/<날짜>-<이름>.md` | 목적, 구성, 규칙, 시안, 예약 참조, 집계 결과, 회고 |
| `docs/events/assets/<이벤트 ID>/` | 기록용 시안·화면 캡처. 최종 서버 이미지의 주제·경로·해시도 문서에 보존 |
| 서버 이미지 저장소 | 홈·집중 배경과 스킨의 실제 이미지 파일. Supabase Storage 전용 버킷 사용 |
| 앱 | 기본 배경·기본 캐릭터, 구형 콘텐츠 연결, 효과 실행 코드와 지원 설정 스키마 |
| 서버 DB | 이벤트·예약·지급 이력, 이미지 주제·경로·해시·규격, 배치·효과 설정, 방별 배경 기간 |
| 기존 스킨 테이블 | 스킨 정의와 실제 보유 상태. 이벤트용 보유 테이블로 복제하지 않음 |

공통 이벤트 ID는 `2026-halloween`처럼 정하고 변경하지 않는다. 매년 재개최할 때 새 ID를 사용하고 이전 문서를 연결한다. 문서가 서버 예약의 실행 입력이 되지는 않는다. 예약 확정 후에는 서버 저장값이 실행 기준이며, 문서와 다르면 서버를 조회해 문서를 정정한다.

문서에는 개인별 UUID·명단·활동 원본이나 비밀 키를 저장하지 않는다. 집계와 작업 ID만 남긴다. 문서 수정 실패가 서버 예약을 취소한 것으로 해석되지 않도록 양쪽 처리 결과를 각각 보고한다.

| 기록 | 필수 내용 |
| --- | --- |
| 이벤트 | 고유 ID, 이름, 문서 경로, 생성·수정 시각 |
| 예약 작업 | 작업 ID, 이벤트 ID, 작업 종류·설정 버전, 지급 스킨 ID 목록, 예정 시각, 대상 방·선택 조건, 확정 대상 UUID 목록, 상태, 요청 중복 방지 키, Cron job ID, 생성·취소·대체 관계와 시각 |
| 실행 시도 | 실행 ID, 작업 ID, 최초 실행·재실행 구분, 시작·종료 시각, 결과, 성공·기보유·실패·제외 건수, 오류 코드·요약 |
| 지급 결과 | 실행 ID, 작업 ID, 사용자 ID, 아이템 종류·ID, 결과, 처리 시각, 오류 코드·요약 |
| 주제별 이미지 | 주제·저장 경로·HTTPS 주소, 파일 해시, 형식·바이트 크기·가로·세로, 등록·검증 상태 |
| 배경 정의 | 세트 ID, 이름, 주제·홈·집중 이미지 경로, 콘텐츠 스키마 버전, 등록·활성 상태 |
| 스킨 표현 정의 | 기존 스킨 ID·캐릭터에 연결된 주제·홈·집중 이미지 경로, 배치 정보, 효과 설정 |
| 효과 설정 | 앱에 등록된 효과 종류·설정 버전, 적용 화면, 종류별 허용 매개변수. 실행 코드는 앱에만 존재 |
| 배경 적용 예약 | 작업 ID, 대상 방 ID, 적용 화면, 배경 세트 ID, 시작·종료 시각, 취소·대체 상태, 시작·종료 Cron 참조와 실행 결과 |

배경 작업의 대상은 사용자 명단이 아닌 방이다. 기간 중 새로 입장한 사용자도 해당 방의 배경을 본다. 공통 예약 작업에는 작업 종류별 설정을 저장하며, 확정 대상 UUID 목록과 사용자별 지급 결과는 스킨 지급에만 필요하다.

예약 작업의 대상과 설정은 서버에서 검증된 구조로 저장한다. 향후 `grant_backgrounds`, `show_banner` 같은 작업을 추가할 수 있지만, 임의 SQL이나 임의 함수 이름을 입력받아 실행하는 구조는 사용하지 않는다.

에셋은 이벤트와 독립된 주제별 라이브러리에 등록하고 여러 이벤트에서 재사용한다. 스킨 보유·착용과 배경 예약의 참조 ID는 유지하지만 새 이미지 버전 UUID는 만들지 않는다. 라이브러리의 경로·표현 정의 수정은 이를 사용하는 이벤트·보유자에게도 반영된다. 과거 UUID 파일·리비전 테이블·예약 필드는 운영 이력으로만 보존하며 현재 앱·서버 조회에는 사용하지 않는다.

예약 변경은 기존 내용을 덮어쓰지 않고 기존 작업을 `superseded`로 종료하고 새 작업을 만든다. 새 작업은 원본 작업을 참조한다. 취소된 작업과 실행 이력도 보존한다. 같은 요청을 재전송하면 같은 작업을 반환하며 Cron을 중복 등록하지 않는다.

## 4. 기본 지급 정책

- 시각은 한국 시간(Asia/Seoul)으로 입력·표시하고 서버에는 `timestamptz`로 저장한다. 초 단위 예약은 지원하지 않는다.
- 연도·날짜·시간·대상·선물이 확정되어야 예약한다. 생략된 시간이나 대상 방을 임의로 선택하지 않는다. 문서에 이미 확정된 값은 재질문 없이 사용한다.
- 기본 대상은 **예약 확정 당시 해당 방의 입장 완료 사용자**다. 기존 지급 함수의 입장 검증 조건을 따른다. 신규 가입자는 자동 추가하지 않는다.
- 대상 방과 명단은 서버에서 검증한다. 실행 시 탈퇴·삭제·방 이동 등으로 대상 자격을 잃은 사용자는 제외 사유를 기록한다. 재실행에서도 대상 명단을 확장하지 않는다.
- 여러 캐릭터의 스킨은 명시된 목록 그대로 지급한다. 현재 캐릭터만 골라 지급하거나 모든 캐릭터 세트를 자동 추측하지 않는다.
- 지급만 수행하고 현재 캐릭터·착용 스킨은 바꾸지 않는다. 지급받은 스킨은 영구 보유하며, 이벤트 종료나 예약 취소로 회수하지 않는다.
- 기보유 스킨은 성공적인 무변경 처리인 `already_owned`로 기록한다. 기존 최초 지급 시각·지급자는 유지한다.
- 대상이 0명이거나 지급 불가·미등록 스킨이 있으면 예약을 거부한다. 예약 시와 실행 시 모두 지급 활성 상태를 검증한다.

### 홈·집중 배경 변경 정책

- 기본은 지정 방의 홈·집중 배경을 한 세트로 변경한다. 홈만 또는 집중만 바꾸는 요청도 지원하며 지정하지 않은 화면은 유지한다.
- 시작과 종료 시각을 모두 지정한다. 적용 구간은 시작 시각 이상, 종료 시각 미만이며 종료 시 기본 배경으로 돌아간다. 기간을 임의로 정하지 않는다.
- 방·화면별로 겹치는 유효 예약은 거부하고 충돌하는 이벤트와 기간을 알려준다. 홈만 바꾸는 행사와 집중만 바꾸는 행사는 동시에 운영할 수 있다. 우선순위·중첩 복귀 규칙은 이번에 만들지 않는다.
- 업로드·규격·배치 검증이 끝나 라이브러리에 등록된 배경 세트만 예약한다. 전환 이후에는 새 세트 ID를 앱 코드에 추가하지 않고 서버가 반환한 이미지 정의로 표시한다. 미지원 스키마·주소·이미지 오류는 기본 배경으로 대체하며 서버 예약 설정을 덮어쓰지 않는다.
- 배경 이미지만 교체하며 캐릭터 위치·타이머·공부 상태·스킨과 UI 색상은 유지한다. 홈·집중 각각의 비율·책상 위치·문자 가독성을 확인한다.
- 화면 진입·앱 복귀·방 변경 시 유효 배경을 조회한다. 화면을 계속 보는 동안은 시작·종료 경계에만 한 번 갱신하도록 예약하며 1분 간격 조회는 추가하지 않는다. 서버 시각과의 차이를 반영하고 복귀 시 다시 확인한다.
- 서버는 취소 여부와 기간으로 현재 유효 배경을 계산한다. 시작·종료 Cron은 실행·운영 기록을 남기지만 배경 유효성은 실행 성공 플래그에만 의존하지 않는다. 종료 Cron 누락으로 배경이 영구 유지되지 않아야 한다.
- 앱에는 배경 시작·종료용 타이머를 두지 않는다. 서버 Cron이 방별 revision을 변경하면 Realtime 신호 후 재조회로 배경을 갱신한다. 오프라인에서는 마지막 조회 결과를 유지하고 Realtime 재연결·화면 재진입·앱 복귀 시 재조회가 성공하면 현재 배경을 반영한다. 아직 받은 적 없는 새 배경의 정시 표시나 앱이 중단된 동안의 즉시 화면 변경은 보장하지 않는다.
- 예약 취소는 시작·종료 작업을 함께 취소한다. 진행 중이면 배경 기간을 즉시 중단하고 기본 배경으로 복귀하도록 서버에 반영한다. 연결 중인 화면은 설정 변경 알림 후 재조회하고, 오프라인 화면은 다음 연결 시 반영한다.
- 진행 중 기간 단축·연장은 기존 기록을 보존한 새 설정으로 대체한다. 활성 배경 설정의 변경·복구와 적용 전후 값도 실행 이력에 남긴다. 스킨 지급 취소·재실행과 독립적으로 처리한다.

### 이미지 전달과 효과 설정

**원칙: 이미지 파일은 서버, 이미지·효과 선택과 매개변수는 서버 DB, 효과 실행 코드는 앱에 둔다.** 이미지가 준비돼 있다는 것과 모든 사용자가 이미 다운로드했다는 것은 구분한다.

#### 주제별 파일 등록

- 홈·집중 파일을 주제별 폴더에 업로드하고 두 파일·메타데이터가 모두 검증된 뒤 라이브러리에 등록한다. 등록 전 파일만으로 지급·배경 예약을 하지 않는다.
- 파일은 Supabase Storage 전용 버킷에 저장한다. 서버 DB에는 이미지 바이트 대신 저장 경로·주소와 규격을 저장한다. 공개 가능한 장식 이미지만 공개 읽기 대상으로 하고 업로드·변경·삭제는 신뢰된 운영 도구로 제한한다. 사용자 정보와 개인 기록은 이미지 버킷에 넣지 않는다.
- 새 파일은 `<주제>/backgrounds/home.png`, `<주제>/skins/<스킨명>/home.png`처럼 분류한다. 이미지 버전 UUID 폴더는 만들지 않는다. 수정은 `home-2.png`처럼 새 파일명을 기본으로 하며, 명시적인 요청이 있으면 같은 경로를 덮어쓰고 해시·규격을 다시 검증·등록한다.
- 초기 형식은 기존 에셋과 같은 정적 PNG로 제한한다. 기본 규격은 홈 1536×1024, 집중 배경 1024×1536이며 스킨은 기존 [스킨 규격](../product/CHARACTER-SKINS-SPEC.md)과 캐릭터별 원본 기준을 따른다. 스킨 투명 배경·책상 기준점·여백·홈/집중 배치 정보를 함께 검증한다.
- 최초 업로드 상한은 PNG 한 파일 5 MiB, 홈·집중 한 세트 합계 10 MiB, 이미지 한 변 2048px로 정한다. 화면별 실제 규격 검증을 함께 수행하고 상한을 넘으면 게시 전에 최적화한다. 규격·상한 변경은 검증과 운영 문서 갱신 후 적용한다. 검증되지 않은 외부 주소나 임의 파일을 앱에 전달하지 않는다.
- 서버 이미지 응답은 HTTPS·지정 Storage 호스트·지정 버킷의 객체 경로만 허용한다. 앱은 콘텐츠 타입·지원 스키마·치수·배치 범위도 검증한다. 공개 이미지 주소를 알아도 스킨 보유·착용 권한이 생기지는 않는다.

#### 앱 로딩과 캐시

- 화면에서 쓰는 홈·집중 배경, 내 착용 스킨, 표시할 친구 스킨과 보유 목록 미리보기부터 가져온다. 전체 스킨 카탈로그를 매번 다운로드하지 않는다.
- 현재 및 다음 배경 기간을 조회할 때 다음 배경을 미리 내려받는다. 이벤트 시작 전에 접속하지 않은 사용자의 정시 표시까지 보장하지 않는다.
- 파일 경로와 검증한 해시를 캐시 키로 사용하고 동일 파일 요청을 공유한다. 기존 이미지 표시 기능과 플랫폼 캐시를 우선 사용해 새 네이티브 의존성 추가를 피한다. 명시적인 보관·정리가 필요한 추가 모듈은 런타임 호환성을 먼저 확인한다.
- 수신·디코딩이 끝난 이미지로 전환한다. 다운로드 중이거나 실패하면 마지막 정상 이미지 또는 해당 화면·캐릭터의 기본 이미지를 사용한다. 실패 때문에 서버의 착용·보유·예약 상태를 초기화하지 않는다.
- 보유 목록은 실제 원격 집중 이미지를 사용한다. 이미지 준비 중·실패 상태를 표시하고 새 스킨의 홈·집중 이미지와 필수 스키마를 확인하기 전에는 적용 준비 완료로 표시하지 않는다.
- 오프라인에서는 남아 있는 캐시를 재사용한다. OS·브라우저가 캐시를 비울 수 있으므로 항상 오프라인 표시를 보장하지 않는다. 사용할 이미지가 없으면 기본 이미지를 표시하고, 배경은 마지막 조회 결과를 유지하며 재연결·화면 재진입·앱 복귀 시 재조회가 성공하면 서버 시각에 맞게 갱신한다.
- 다운로드는 공부 시작·중지·기록 저장을 막지 않는다. 동시에 보이는 친구 수와 화면 수요에 맞춰 요청·메모리 사용을 제한한다.
- 현재 앱 코드의 로컬 ID 목록만으로 원격 스킨을 미지원 처리하지 않도록 변경한다. 서버 표현 정의를 검증해 표시하고, 기본 캐릭터와 기존 스킨의 로컬 연결은 구버전·오프라인 대체용으로 보존한다.

#### 준비된 효과 조합

- 서버는 효과의 종류·설정 버전·화면별 매개변수를 전달한다. JavaScript·스크립트·임의 수식은 전달하거나 실행하지 않는다.
- 첫 전환은 현재 구현된 `warmSteam`을 서버 설정으로 연결한다. 눈·반짝임·꽃잎은 현재 지원 목록에 없으며 별도 효과 구현과 업데이트 후 등록할 수 있다.
- 각 효과가 공개한 매개변수만 허용한다. 우선 기존 홈·집중의 위치·폭·투명도를 지원한다. 색·속도·밀도는 해당 효과 렌더러와 설정 스키마가 지원할 때만 변경할 수 있다.
- 위치·폭은 원본 캔버스 기준 정규화 좌표, 투명도는 0~1 등 종류별 유효 범위를 정하고 서버·앱에서 검증한다. 효과 수·입자 수·속도에도 종류별 성능 상한을 둔다.
- 스킨에 연결된 효과는 착용 중 해당 캐릭터에 적용된다. 효과 설정만 바꾸는 것은 기존 라이브러리 표현 정의 갱신로 처리하며 별도 아이템을 지급하지 않는다.
- 알 수 없는 효과 종류·버전은 건너뛰고 스킨 이미지는 표시한다. 잘못된 필수 이미지·배치 스키마는 기본 이미지로 대체한다. 동작 줄이기·화면 비활성화·기존 효과 끄기 설정을 유지한다.
- 새 동작은 앱 효과 목록에 구현하고 EAS 업데이트로 전달한 뒤 사용한다. 새 네이티브 기능까지 필요하면 APK 호환성을 별도 검토한다. 화면 전체 독립 효과와 효과 아이템의 보유·상점 기능은 후속 범위다.

#### 최초 전환과 기존 사용자

- 기존 예약·스킨 ID·보유·착용과 지급 이력은 유지한다. 새 필드는 기존 응답과 호환되게 추가하고 과거 에셋 참조를 즉시 제거하지 않는다.
- 원격 이미지와 효과 설정을 이해하는 최초 앱 업데이트 적용이 필요하다. 현재 의존성으로 처리하는 방향을 우선해 EAS 전달을 목표로 하되 실제 런타임 호환성 검토를 생략하지 않는다.
- 최초 업데이트 이전 앱은 새 원격 전용 콘텐츠를 표시할 수 없다. 기존 연결 또는 기본 이미지와 업데이트 안내로 처리한다. 서버에 이미지를 올렸다는 사실만으로 모든 앱에 표시됐다고 기록하지 않는다.
- 전환 이후 지원 규격의 이미지·기존 효과 설정은 앱 업데이트 없이 추가할 수 있다. 미지원 효과 동작·콘텐츠 스키마·캐릭터 종류를 사용하는 경우 필요한 앱 업데이트를 안내한다.

## 5. 특정 날짜 실행

Supabase Cron은 지정 일정에 DB 함수를 호출할 수 있다. 이번에는 주기적으로 예약 목록을 조회하지 않고 **예약 작업마다 해당 월·일·시·분의 Cron을 등록**한다. 등록된 함수에는 작업 ID만 전달한다. 배경 예약에는 시작·종료 두 작업을 연결하고, 두 시각 모두 아래 예약 가능 범위를 만족해야 한다. 같은 요청의 등록·변경·취소는 두 작업을 함께 처리한다.

Cron 표현식에 연도 필드가 없으므로 다음 제한과 보호 장치를 둔다.

1. 최초 버전은 등록 시점부터 향후 1년 이내이며, 계산한 Cron의 다음 실행 시각이 요청 시각과 일치하는 예약만 허용한다. 윤일과 연말의 한국 시간→UTC 날짜 변경도 검증한다.
2. 실행 함수에서 전체 예정 시각과 상태를 다시 검사한다. 예정 시각 전에는 지급하지 않는다. 자동 실행 허용 기간은 예정 시각부터 24시간 미만이다.
3. 예정 시각에 한 차례 실행하고, 성공·일부 실패·실패 결과를 기록한 뒤 해당 Cron을 해제한다. 반복 재시도 작업은 등록하지 않는다.
4. 취소·대체·이미 완료된 작업은 지급하지 않는다. 남아 있는 Cron만 정리한다. 허용 기간을 넘긴 호출은 `missed`로 기록하고 지급 없이 Cron을 해제한다.

서버가 해당 시각에 중단되면 실행이 누락될 수 있다. 이를 자동 보정하거나 정확한 시각의 지급을 보장하지 않는다. 관리자가 결과 조회 시 미실행·시간 경과 작업을 확인하고 재실행한다. 일상적인 예약 확인용 Cron은 추가하지 않는다.

실제 프로젝트의 Cron 시간대와 실행 권한을 확인한 뒤 등록한다. 현재 마이그레이션의 GMT 기준을 무조건 가정하지 않는다. DB 지급과 결과 저장, 정상 종료 시 Cron 해제는 가능한 한 같은 트랜잭션에서 처리한다.

## 6. 실행·실패·동시 요청

아래 사용자별 지급·재실행 규칙은 스킨 작업에 적용한다. 배경 작업은 방별 기간 설정의 원자적 변경과 시작·종료 기록을 단위로 처리하며, 4절의 배경 정책을 따른다.

- 작업 행 잠금으로 실행·변경·취소·재실행을 직렬화한다. 변경·취소가 먼저 확정되면 원래 작업은 지급되지 않는다. 실행이 먼저 확정되면 완료 사실을 알리고 변경·취소로 회수하지 않는다.
- 사용자별 스킨 묶음 지급과 해당 결과 기록은 함께 확정한다. 한 사용자 묶음의 일부가 실패하면 그 사용자의 이번 신규 지급 전체를 되돌리고 실패로 기록한다. 다른 사용자는 계속 처리할 수 있다.
- 여러 사람이 일부 성공하면 `partial_failed`, 전부 실패하면 `failed`, 전부 처리되면 `completed`다. 기보유·자격 상실 제외는 별도 집계한다. 대상 모두 제외되어도 그 사실을 결과에 명시한다.
- 결과에는 사용자 수와 사용자×아이템 건수를 구분한다. 기보유와 신규 지급이 섞인 경우에도 합계가 검증되어야 한다.
- 예상 가능한 지급 오류는 내부 예외 처리로 포착해 지급을 되돌린 뒤 실패 기록과 Cron 해제를 확정한다. 시간 초과·DB 중단처럼 전체 트랜잭션이 실패하면 기록도 되돌아갈 수 있다. 조회 시 Cron 실행 이력과 작업·보유 기록을 대조해 미확정으로 표시한다.
- 재실행은 실패·미처리 사용자만 처리한다. 기존 성공·기보유는 반복 지급하지 않는다. 실행 시도는 새로 남기되 원래 작업·대상·선물은 유지한다.
- 누락 실행이나 전체 중단은 별도 재실행 요청으로 복구한다. 자동 실행의 24시간 제한을 넘긴 지급은 관리자의 명시적 복구 요청으로만 허용한다.
- 복구 후 남은 Cron도 해제한다. Cron 정리 실패는 지급 실패와 구분해 표시하고 정리 작업만 다시 수행한다.

## 7. 채팅 운영 방법

아래 예시는 구현 후 지원할 요청 형식이다. 현재 실행 가능한 명령이나 이미 등록된 예약을 뜻하지 않는다.

### 이벤트 기록

> “2026 크리스마스 이벤트 문서 만들어줘. 겨울 배경과 스킨, 홈 눈 효과를 계획 중이야.”

GPT가 템플릿으로 문서를 만들고 목록에 추가한다. 미지원 구성도 계획으로 기록할 수 있다. 문서 작성 요청만으로 서버 작업을 예약하지 않는다.

### 새 이미지·스킨·효과 등록 (후속 전환 후)

> “이 홈·집중 이미지를 겨울 배경으로 등록해줘.”
> “이 토끼 스킨을 등록하고 기존 김 효과를 이 위치와 크기로 붙여줘.”

GPT가 파일·규격·배치와 지원 효과를 확인하고 주제별 저장 경로에 업로드한다. 두 화면 이미지와 정의를 검증한 뒤 라이브러리에 등록·활성화하고 문서에 주제·참조 ID·파일 경로·해시·효과 설정·미리보기를 기록한다. 업로드만 성공하고 등록이 실패하면 미등록 파일로 남겨 보고한다. 등록 요청만으로 실제 지급이나 배경 기간을 예약하지 않는다. 미지원 효과는 자동 구현·배포하지 않고 필요한 후속 작업으로 기록한다.

### 예약

> “이 이벤트의 준비된 스킨 4종을 2026년 12월 25일 오전 9시에 1번방 전원에게 지급 예약해줘.”

1. 이벤트 문서, 지정 스킨 ID, 이미지 업로드·검증·게시 상태, 필요한 콘텐츠 스키마·효과 지원과 실제 서버 활성 상태를 확인한다. 최초 전환 코드를 지원하는 앱의 준비 상태도 확인한다.
2. 대상 방의 입장 완료 명단을 조회해 확정한다. 시간이 과거이거나 필수 정보가 불명확하면 예약하지 않고 필요한 정보만 묻는다.
3. 서버에 이벤트와 작업·Cron을 등록한다. 저장과 Cron 등록이 부분 성공한 상태를 예약 완료로 보고하지 않는다.
4. 서버에서 작업과 Cron을 다시 조회해 시각·대상·선물이 일치하는지 확인한다.
5. 문서에 작업 ID와 확인 시각을 기록한다. 응답에는 이벤트 이름, 한국 시간, 대상 방·인원, 선물, 예약 ID를 남긴다.

예약 권한이 명확한 요청에는 별도 반복 승인을 요구하지 않는다. 배경 개인 보유 지급·스킨과 독립된 화면 전체 효과 등 미지원 작업은 예약 완료에 포함하지 않는다. 기존 스킨 효과 설정은 공개된 스킨 표현 정의에 따라 적용하며 별도 지급 작업으로 만들지 않는다.

### 홈·집중 배경 예약

> “2026년 10월 31일 오전 9시부터 11월 1일 오전 6시까지 1번방 홈·집중 배경을 핼러윈 세트로 바꿔줘.”

서버 배경 라이브러리 등록 상태·두 이미지 경로·해시, 앱의 최초 전환 지원 여부, 적용 방, 시작·종료 시각과 겹치는 예약을 검증한다. 매번 새 이미지에 대한 EAS 배포를 요구하지 않는다. 기간 설정과 시작·종료 작업을 함께 등록하고 재조회한다. 문서와 응답에는 배경 세트 ID, 대상 방·화면, 기간, 예약 ID와 두 실행 작업 참조를 남긴다.

> “그 배경 예약 취소해줘.” / “진행 중인 핼러윈 배경 지금 내려줘.”

시작 전에는 연결된 두 작업을 취소한다. 진행 중에는 기간을 중단하고 종료 Cron도 해제하며, 다음 유효 설정 조회부터 기본 배경을 반환한다. 스킨 보유 내역은 유지한다. 배경 종료 누락 복구는 지난 시작 작업을 재실행하지 않고 현재 기간·취소 상태에 맞게 정리한다.

### 조회

> “예약된 이벤트 보여줘.” / “크리스마스 선물 지급됐어?” / “지금까지 한 이벤트 정리해줘.”

예약·결과는 서버를 조회하고 설명·자료는 문서를 읽어 함께 답한다. 예약 시각이 지났는데 실행 기록이 없으면 미실행·확인 필요로 표시한다. 결과 조회 과정에서 지급을 자동 실행하지 않는다. 문서 갱신 시 집계 기준·확인 시각도 남긴다.

### 변경·취소

> “크리스마스 스킨 지급을 12월 24일 오후 8시로 바꿔줘.” / “그 지급 예약 취소해줘.”

스킨 지급은 미실행 작업만 변경·취소한다. 날짜 변경 시 기존 확정 대상은 유지하며, 대상 갱신은 별도 요청으로 처리한다. 같은 트랜잭션에서 기존 Cron 해제와 새 예약 확정을 처리하고 결과를 재조회한다. 취소는 지정한 작업을 멈추며 이벤트 문서 전체를 삭제하거나 다른 구성까지 취소하지 않는다. 진행 중 배경은 위 배경 중단·기간 변경 정책을 따른다.

### 실패 복구

> “이 예약에서 지급 실패한 사람만 다시 지급해줘.” / “서버 중단으로 놓친 예약을 지금 실행해줘.”

원래 결과·명단·스킨 활성 상태를 확인해 필요한 사용자만 재실행한다. 성공한 사용자에게 재지급하거나 신규 구성원을 추가하지 않는다. 새 실행 ID와 결과를 문서에 반영한다.

### 행사 종료와 재개최

> “이번 이벤트 결과 기록해줘.” / “작년 이벤트 참고해서 올해 계획 만들어줘.”

실제 실행 집계를 문서에 옮기고 활동·이미지·회고를 보완한다. 선물 지급 완료가 문서 전체 이벤트의 종료를 의미하지는 않는다. 재개최는 새 이벤트 ID와 새 문서를 만들며 과거 규칙·예약을 수정하지 않는다.

## 8. 운영 도구와 권한

구현 산출물은 이벤트 관리용 서버 함수, 이를 호출하는 운영 스크립트, 요청을 문서·서버 작업에 연결하는 프로젝트 스킬이다. 스킬에는 기록·예약·조회·변경·취소·복구 절차와 지원 작업 목록을 넣는다. 예약은 서버가 실행하므로 채팅과 운영 PC가 꺼져 있어도 동작한다.

서버 쓰기 작업은 기존 운영 환경의 신뢰된 관리자 자격으로만 실행한다. 공개 앱에서 예약 생성·수정·실행 함수를 호출할 수 없도록 권한을 제한한다. 노출 스키마의 테이블에는 RLS를 적용하고 운영 기록의 일반 사용자 조회를 차단한다. 앱에는 소속 방의 현재·다음 배경 설정과 경계 시각만 반환하는 읽기 경로를 제공하고, 다른 방의 설정이나 관리자 실행 이력은 노출하지 않는다. Cron 실행 역할에는 필요한 범위의 권한만 부여한다.

서비스 키는 기존 비공개 환경에서만 읽고 명령 인자·문서·로그·앱 코드에 넣지 않는다. 오류에는 비밀 값이나 불필요한 개인정보를 기록하지 않는다. 이번에는 사용자 알림이나 Discord 발송을 추가하지 않는다.

## 9. 구현 순서와 완료 기준

1. 현재 서버 스킨 구조·운영 권한·Cron 설정을 확인하고 데이터 모델과 서버 함수를 구현한다.
2. 주제별 이미지 저장소·독립 라이브러리·콘텐츠 정의·업로드 검증과 등록 기능을 추가한다. 기존 스킨·배경 ID와 보유·착용 내역은 유지한다.
3. 앱의 배경·스킨 해석을 서버 정의로 연결한다. 홈·집중·친구·프로필·보유 목록을 함께 전환하고 미리 다운로드·캐시·대체 표시를 구현한다. 현재 효과 렌더러에 설정 검증을 연결한다.
4. 운영 스크립트와 프로젝트 스킬에 이미지 업로드·콘텐츠 등록·검증·게시·기존 효과 설정 절차를 추가한다. 미구현 명령을 현재 사용 가능한 것으로 안내하지 않는다.
5. 호환되는 최초 앱 업데이트를 배포·적용해 테스트방의 서버 이미지·캐시·효과를 검증한다. 네이티브 의존성을 추가하지 않는 방향을 우선하며, APK 필요 여부는 실제 변경과 설치 런타임을 검토해 확정한다.
6. 이후 새 배경·스킨을 EAS 배포 없이 등록하고 예약해 표시되는지 검증한다. 운영방 실제 행사는 별도 요청으로 예약한다.

완료에 필요한 검증:

- 한국 시간·UTC 변환, 연말·윤일, 과거·불명확 시각 거부, 다음 Cron 실행 시각 일치.
- 재요청·동시 실행·재실행에서 중복 예약·중복 지급 없음.
- 예약 당시 대상 유지, 신규 가입자 미포함, 방 이동·탈퇴 제외.
- 묶음 지급의 사용자별 원자성, 기보유 정보 보존, 일부 실패 기록과 복구.
- 취소·변경과 실행의 경합, 구 Cron 미지급, 다음 해 중복 지급 방지.
- 서버 중단·시간 초과·Cron 정리 실패·예약 등록 부분 실패 복구.
- 일반 앱 권한의 운영 API 접근 거부, 기존 스킨 선택·표시 유지.
- 배경 시작·종료·진행 중 중단, 홈만·집중만 변경, 겹치는 예약 거부, 다른 방 설정 접근 거부.
- 배경 기간 중 신규 입장, 화면 유지·재진입·앱 복귀·방 변경, 종료 Realtime 수신·미수신과 재연결, 미지원 에셋의 기본 배경 대체.
- 시작·종료 Cron 누락 시에도 기간에 맞는 배경 반환, 스킨과 배경 작업의 독립 복구.
- 홈·집중 배경을 Storybook 웹에서 시각 확인하고 배포 대상 Android·iPhone 웹앱에서 별도 확인. 실제로 확인한 환경과 한계를 기록.
- 실제 Supabase Cron 실행을 테스트방에서 확인. 격리 DB 검증만으로 이를 통과했다고 보고하지 않음.
- 서버에만 등록한 새 스킨·배경 ID가 코드 수정 없이 홈·집중·친구·프로필·보유 목록에 표시되고, 보유·착용 권한이 유지됨.
- 업로드 일부 실패·404·손상 파일·잘못된 주소·미지원 스키마·캐시 삭제에서 기본 이미지 대체 및 복구. 다운로드 전에는 준비 완료로 오인하지 않음.
- 파일 경로/해시 변경 시 이전 이미지 캐시와 혼동하지 않고 라이브러리 참조 이벤트에 반영됨. 기존 UUID 이력·파일은 기록으로 보존하지만 해당 조회/등록 API는 제거함.
- 오프라인 캐시 재사용과 배경 유지·재연결 후 종료 반영, 캐시가 비워진 오프라인 재시작의 기본 이미지 대체. 이미지 로딩이 타이머·공부 저장을 지연시키지 않음.
- 기존 효과 설정 변경의 반영, 미지원 종류·과도한 매개변수 무시·거부, 효과 실패 시 이미지 표시 유지.
- 최초 지원 업데이트 이전 앱의 기존 이미지·기본 이미지 대체와 이후 앱의 원격 이미지 처리 차이를 검증. 새 이미지별 EAS 배포 없이 운영 가능한지 확인.
- 린트·타입 검사와 관련 서버 테스트 통과. 문서와 서버 예약의 일치 확인.

## 스킨 지급 알림 추가

- 스킨 신규 지급이 커밋된 뒤 사용자·작업당 한 번 기존 푸시 발송 기능을 호출한다. 기존 보유·실패·제외·배경 변경에는 보내지 않는다.
- 예약의 `notification`은 선택 항목이다. 기본 문구 자동 생성, 제목·본문 개별 지정, `enabled: false`를 지원한다.
- 문구와 수신자는 서버 기록으로 고정한다. 큐는 private이며 제한된 서버 함수만 사용한다. HTTP 호출은 비동기이고 푸시 실패는 지급을 취소하지 않는다.
- 같은 알림 UUID로만 재요청하며 기존 발송 함수의 중복 방지를 재사용한다. 알림 처리 완료·푸시 서비스 접수·실제 기기 표시는 구분한다.
- 앱 타이머·예약 목록 주기 조회·새 APK·알림 클릭 시 스킨 상세 이동은 추가하지 않는다. 실제 서버 반영·기기 수신 검증 상태는 운영 기록으로 남긴다.

## 주제별 라이브러리 전환

새 에셋은 schemaVersion 2·theme·home/focus 파일 경로로 등록한다. 관리자가 이미지 리비전 UUID를 발급하거나 초안·리비전 게시를 거치지 않는다. 주제별 목록을 조회하고 기존 스킨 ID·배경 참조 ID로 이벤트에서 재사용한다. 앱과 운영 도구는 주제별 형식으로 통일하고 버전 1 등록·게시·읽기 호환과 p_schema_version 선택을 제거한다. UUID 파일·과거 기록은 보존하지만 현재 조회에 사용하지 않는다. 방별 Realtime revision 번호는 이미지 버전이 아니라 변경 신호이므로 유지한다.
