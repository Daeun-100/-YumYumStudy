# 캐릭터 이벤트 스킨 구현 결과

기준 브랜치 `develop`에서 `codex/character-event-skins`를 생성했다. 실제 앱의 보유 스킨 화면과 스토리북이 같은 UI를 사용하며, 서버 변경은 마이그레이션으로 준비했다. 운영 서버 반영은 2026-10-28 완료했으며, APK·OTA 배포는 실행하지 않았다.

## 구현 내용

- 프로필의 닉네임 옆 연필 수정 버튼과 닉네임 아래 보유 스킨 진입 항목
- 이벤트 스킨만 캐릭터별로 표시하는 목록, 집중 이미지 미리보기, 적용·해제
- 다른 캐릭터의 스킨 적용 시 캐릭터와 스킨 동시 변경
- 공통 이미지 선택을 통한 홈·집중·친구 아바타·프로필 반영
- 원격 프로필 갱신 시 관리자 적용 상태 반영과 오래된 프로필 응답 방지
- 미지원 스킨의 기본 이미지 대체, 업데이트 안내와 적용 제한
- `character_skins`, `user_skins`와 기존 `profiles` 확장. 별도 관리자 로그 없음
- 서비스 권한 전용 관리자 지급·적용 함수 및 운영 스크립트
- 중복 지급 시 보유 내역과 최초 지급 정보 유지
- 이름만 수정하거나 같은 캐릭터를 선택하면 스킨 유지. 다른 기본 캐릭터 선택 시 스킨 해제

현재 스킨 ID는 `bunny-toothache`다. 실제 사용하는 파일과 배치 보정값은 `src/design/skin-artwork.ts`에서 확인한다. 지급은 비활성 상태로 시작한다.

## 검증 결과와 범위

- 린트와 타입 검사 통과
- 스토리북 정적 빌드 통과
- Android Hermes 번들과 이미지 export 통과. APK 설치 검증은 아님
- 관련 단위·회귀 검사 20개 통과: 프로필·친구 응답, 미지원 스킨, 원격 착용 갱신 포함
- 전체 검사 202개 중 200개 통과. 실패 2개는 기존 테스트의 macOS Java 경로와 Windows에서 URL pathname을 파일 경로로 쓰는 문제이며 이번 스킨 구현과 별개
- 격리 PostgreSQL에서 기존 앱 마이그레이션과 새 마이그레이션 재생 통과. 지급·적용·해제, 교차 캐릭터, 중복 지급, 미보유 거부, 테스트방·운영방 대상 확인, 입장 제한, RLS 및 관리자 함수 접근 제한 통과
- 스토리북에서 프로필 진입 → 치통 토끼 선택 → 토끼로 변경하고 적용 → 기본 토끼로 해제 확인

격리 DB 검증은 운영 DB와 분리해 수행했다. 서버 반영 후에는 테스트방 프로필을 사용하는 실제 DB 검증을 추가 수행하고 모든 테스트 변경을 롤백했다. 외부 cron·Vault와 Realtime 전송은 대체 환경으로 검증했으므로 실제 Supabase Realtime 연결, 기기 간 전파 및 Android·iOS 기기 시각 검증은 배포 전 별도 확인이 필요하다.

## 반영 순서

2026-10-28 서버 반영 완료: `20261028125054_character_event_skins`, `20261028125307_index_profile_skin`. 실서버에서 지급 비활성 거부·지급과 적용·중복 지급·본인 목록 조회·타인 데이터 제한·프로필 및 친구 응답·같은 캐릭터 스킨 유지·다른 캐릭터 선택 시 해제·미보유 스킨 거부를 검사하고 롤백했다. 이후 프로필 수 25개, 보유 내역 0개, 착용자 0명, 지급 비활성 상태를 확인했다.

성능 검사에서 발견한 새 프로필 외래 키의 인덱스를 보완했다. 보안 검사의 [익명 로그인 사용자 정책 안내](https://supabase.com/docs/guides/database/database-advisors?queryGroups=lint&lint=0012_auth_allow_anonymous_sign_ins)는 앱의 익명 인증 계정 중 입장 완료된 본인에게만 접근을 허용하는 의도된 정책이다. 미인증 `anon`의 테이블 조회·목록 RPC와 일반 사용자의 관리자 함수 실행 권한은 모두 없음을 확인했다. 기존 보안 안내 항목은 별도 변경하지 않았다.

1. 기존 마이그레이션 적용 이력을 확인하고 신규 스킨 마이그레이션을 서버에 반영한다.
2. 테스트방 사용자에게 스킨 지급·적용을 확인하고 기존 앱의 프로필·친구 조회가 유지되는지 확인한다.
3. 설치 APK와의 호환성을 검토해 앱 코드를 배포한다.
4. 이미지 전달을 검증한 후 운영 지급을 활성화한다.

관리자 화면은 이번 범위에 포함하지 않았다. 구체적인 운영 명령은 [운영 문서](../../CHARACTER-SKINS-OPERATIONS.md)를 따른다. 운영 도구의 서비스 키는 앱에 넣지 않는다.
