# 캐릭터 이벤트 스킨 기능 명세서

작성일: 2026-10-28  
상태: 기능 구현·서버 반영 및 검증 완료, 앱 배포 예정
이미지 방식: 현재 구현은 앱 에셋 포함 및 OTA 배포

> 배경·스킨을 서버 이미지로 전달하고 기존 효과를 설정으로 조합하는 [후속 전환 명세](../proposals/EVENT-OPERATIONS-SPEC.md#이미지-전달과-효과-설정)를 2026-10-29 확정했다. 아래의 앱 에셋·새 이미지별 OTA·로컬 ID 제한은 현재 구현 설명이며, 후속 전환의 목표 동작은 연결한 명세를 따른다. 기존 지급·보유·착용 정책은 유지한다.

## 1. 목적

친구에게 현실에서 생긴 이벤트를 앱 속 캐릭터 모습에 반영한다. 관리자는 이벤트 스킨을 친구에게 지급하고 직접 적용할 수 있으며, 친구도 자신의 보유 스킨 목록에서 원하는 스킨을 선택할 수 있다. 지급받은 스킨은 이벤트가 끝나도 보관한다.

예를 들어 토끼 캐릭터를 사용하는 친구가 아프면, 관리자가 홈·집중 이미지로 구성된 ‘아픈 토끼’를 지급하면서 적용한다. 친구는 이후 기본 모습이나 다른 보유 스킨을 직접 선택할 수 있다.

## 2. 이미지 저장과 배포

- 홈·집중 이미지는 프로젝트 에셋으로 포함한다. 이미지 서버 저장 및 원격 이미지 로딩은 이번 범위에서 제외한다.
- 새 스킨 이미지와 연결 코드는 OTA로 배포한다. 새 이미지를 추가할 때마다 OTA 배포가 필요하다.
- 설치된 APK가 OTA를 지원하고 변경 코드와 호환되면 APK 재설치 없이 전달할 수 있다. 네이티브 변경을 함께 배포할 경우 APK 필요 여부를 별도로 확인한다.
- 서버에는 스킨 정의, 친구별 보유 내역, 현재 적용 상태를 저장한다.
- 이미 앱에 전달된 스킨은 추가 앱 배포 없이 지급·적용할 수 있다.
- 기본 캐릭터 이미지는 항상 사용할 수 있도록 유지한다.

## 3. 용어와 스킨 구성

| 용어 | 정의 |
|---|---|
| 기본 캐릭터 | 토끼·곰·고양이 등 사용자가 선택한 캐릭터 종류 |
| 기본 스킨 | 해당 캐릭터의 기존 홈·집중 모습 |
| 이벤트 스킨 | 아픈 모습 등 특정 이벤트를 표현하는 추가 모습 |
| 보유 스킨 | 관리자에게 지급받아 선택할 수 있는 스킨 |
| 적용 스킨 | 현재 홈·집중 화면에 표시하는 스킨 |

이벤트 스킨은 특정 기본 캐릭터에 속하지만, 현재 선택한 캐릭터와 관계없이 보유 스킨에서 바로 적용할 수 있다. 예를 들어 곰을 사용하던 친구가 ‘아픈 토끼’를 적용하면 기본 캐릭터는 토끼로, 적용 스킨은 아픈 토끼로 함께 변경된다.

| 스킨 항목 | 설명 |
|---|---|
| 스킨 ID | 변경하지 않는 고유 식별자 |
| 이름 | 보유 스킨 목록에 표시할 이름 |
| 대상 캐릭터 | 스킨이 속한 캐릭터 종류이며 적용 시 함께 선택됨 |
| 홈 이미지 | 홈 화면에서 사용할 이미지 |
| 집중 이미지 | 집중 화면에서 사용할 이미지 |
| 미리보기 | 집중 이미지를 사용하며 별도 미리보기 파일은 만들지 않음 |
| 배치 정보 | 화면별 크기와 위치 보정값 |

홈·집중 이미지가 모두 준비된 스킨만 지급 가능하게 등록한다. 투명 배경과 이미지 크기·여백 기준을 정하고 각 화면에서 배치를 확인한다.

## 4. 보유 스킨 전용 진입 항목

프로필 화면에 기존 캐릭터 선택과 구분되는 **‘보유 스킨’ 항목을 별도로 추가**한다. 해당 항목을 누르면 독립된 보유 스킨 목록 화면으로 이동한다.

- 항목 이름: 보유 스킨
- 목적: 지급받은 스킨 확인 및 적용
- 기본 캐릭터 선택 기능은 기존 위치에 유지한다.
- 프로필 이미지 옆에 닉네임과 작은 연필 수정 버튼을 두고, 닉네임 아래에 ‘보유 스킨 N개 ›’를 배치한다. 카드나 별도 캐릭터 섹션을 만들지 않으며 프로필 영역과 주간 목표 사이에 구분선을 둔다.
- 목록 화면에서 뒤로 이동하면 프로필 화면으로 돌아온다.

## 5. 보유 스킨 목록과 선택

- 지급받은 이벤트 스킨만 캐릭터별로 묶어 표시한다. 기본 캐릭터·기본 스킨 카드는 표시하지 않으며, 보유 이벤트 스킨이 없는 캐릭터 그룹은 숨긴다.
- 각 항목에 **집중 이미지 미리보기**, 스킨 이름, 현재 적용 여부를 표시한다.
- 지급받지 않은 이벤트 스킨은 표시하지 않는다.
- 기본 캐릭터 선택은 기존 프로필 수정 화면에서 유지한다. 보유 이벤트 스킨이 없으면 빈 상태 안내를 표시하고 목록과 적용 버튼은 숨긴다.
- 이벤트 스킨 적용 중에는 별도의 ‘스킨 해제 · 기본 모습으로’ 버튼으로 현재 캐릭터의 기본 모습으로 돌아갈 수 있다. 기본 모습은 목록 카드로 표시하지 않는다.
- 다른 캐릭터의 보유 스킨도 목록에서 바로 선택할 수 있다. 캐릭터 선택 화면을 먼저 거칠 필요는 없다.
- 현재 캐릭터의 스킨은 ‘적용’, 다른 캐릭터의 스킨은 ‘토끼로 변경하고 적용’처럼 캐릭터 변경을 알리는 버튼으로 저장한다. 저장 중 중복 요청을 막는다.
- 다른 캐릭터의 스킨을 적용할 때는 기본 캐릭터와 적용 스킨을 함께 저장한다.
- 저장 성공 후 현재 적용 표시와 관련 화면을 갱신한다.
- 저장 실패 시 기존 캐릭터와 적용 스킨을 모두 유지하고 재시도를 안내한다.
- 목록 조회 실패 시 다시 불러올 수 있어야 한다.

## 6. 관리자 지급과 적용

| 작업 | 동작 |
|---|---|
| 스킨 지급 | 특정 친구의 보유 목록에 추가 |
| 지급하면서 적용 | 보유 목록 추가와 현재 적용 변경을 함께 처리 |
| 보유 스킨 적용 | 친구가 이미 보유한 스킨으로 변경 |
| 기본 모습 적용 | 해당 친구의 기본 스킨으로 변경 |

- 같은 스킨을 중복 지급해도 보유 내역은 하나만 유지한다.
- 보유하지 않은 스킨은 지급 없이 적용할 수 없다.
- 현재 기본 캐릭터와 다른 종류의 스킨도 적용할 수 있으며, 대상 친구의 기본 캐릭터를 스킨에 맞춰 함께 변경한다.
- 지급하면서 적용하는 요청은 지급·캐릭터 변경·스킨 적용이 모두 성공하거나 모두 반영되지 않도록 처리한다.
- 관리자 적용 후에도 친구가 직접 다른 보유 스킨이나 기본 스킨을 선택할 수 있다.
- 관리자와 친구의 요청이 연속으로 발생하면 서버에서 마지막으로 정상 저장된 선택을 적용한다.
- 지급과 관리자 적용은 서버에서 관리자 권한을 검증한다.

관리자 전용 화면 제작 여부는 추후 결정한다. 미제작 시에도 권한이 검증된 운영 수단으로 지급·적용할 수 있어야 한다. 일반 사용자 앱에 관리자 비밀 키를 포함하지 않는다.

## 7. 화면별 표시 규칙

| 화면 | 표시 이미지 |
|---|---|
| 홈의 내 캐릭터 | 내 적용 스킨의 홈 이미지 |
| 집중 화면의 나와 친구 | 각 사용자의 적용 스킨 집중 이미지 |
| 홈의 친구 아바타 | 각 친구의 적용 스킨 홈 이미지 |
| 친구 목록 | 각 친구의 적용 스킨 집중 이미지 |
| 일반 프로필 아바타 | 적용 스킨의 홈 이미지 |
| 기본 캐릭터 선택 | 기존 기본 캐릭터 이미지 |
| 보유 스킨 목록 미리보기 | 각 스킨의 집중 이미지 |
| 휴가 화면 | 기존 기본 캐릭터 휴가 이미지 |

집중 화면의 달성 효과와 휴가 이미지는 적용 후의 기본 캐릭터 종류를 기준으로 표시한다. 곰에서 아픈 토끼로 바꾸면 달성 효과와 휴가 이미지도 토끼 기준을 사용한다. 새 스킨 이미지와 효과의 겹침을 검증하고 필요하면 배치를 보정한다. 적용 정보 변경은 기존 프로필·친구 정보 갱신 경로를 통해 다른 사용자 화면에도 반영한다.

## 8. 기본 캐릭터 변경

- 기존 캐릭터 선택 화면에서 다른 기본 캐릭터로 변경하면 새 캐릭터의 기본 스킨으로 초기화한다. 같은 캐릭터를 다시 선택하는 것만으로 현재 스킨을 해제하지 않는다.
- 보유 스킨 목록에서 다른 캐릭터의 이벤트 스킨을 적용하면 해당 캐릭터와 이벤트 스킨을 함께 선택한다. 이 경우 기본 스킨으로 초기화하지 않는다.
- 이전 캐릭터의 이벤트 스킨 보유 내역은 삭제하지 않는다.
- 이전 캐릭터의 보유 스킨도 전체 목록에서 언제든 바로 적용할 수 있다.

## 9. 서버와 앱의 관리 정보

| 위치 | 정보 |
|---|---|
| 서버 스킨 정의: `character_skins` 추가 | 스킨 ID, 이름, 대상 캐릭터, 지급 가능 상태 |
| 서버 보유 내역: `user_skins` 추가 | 사용자 ID, 스킨 ID, 지급 시각, 지급 관리자 |
| 서버 적용 상태: 기존 `profiles` 변경 | 기존 캐릭터 정보에 적용 스킨 ID와 변경 시각 추가. 적용 스킨 ID가 비어 있으면 기본 모습 |
| 앱 스킨 정의 | 스킨 ID에 연결된 홈·집중 이미지와 화면별 배치 정보 |

서버 구조는 테이블 2개 추가와 기존 `profiles` 변경으로 구성한다. 별도 관리자 작업 기록 테이블(`skin_admin_logs`)은 만들지 않는다. 보유 내역에 최초 지급자와 지급 시각을 남기며, 중복 지급으로 이를 덮어쓰지 않는다. 이후 관리자 착용 변경 이력은 별도로 저장하지 않는다. 관리자 지급·적용 기능과 서버 권한 검증은 유지한다.

사용자는 자신의 보유 목록을 조회하고 모든 기본 스킨 및 보유한 이벤트 스킨을 적용할 수 있다. 서버는 스킨 정의에 따라 대상 캐릭터를 결정하고 캐릭터와 스킨을 하나의 작업으로 저장한다. 현재 캐릭터가 다르다는 이유로 적용을 거부하지 않으며, 캐릭터와 스킨의 소속이 어긋난 상태로 저장하지 않는다. 다른 친구에게 보여줄 현재 적용 스킨 정보는 기존 프로필 조회 권한에 맞춰 제공한다.

앱 시작 및 화면 재진입 시 저장된 적용 상태를 복원한다. 서버 조회가 실패하거나 오프라인인 경우 마지막으로 확인한 표시 상태 또는 기본 이미지를 사용하며, 서버의 실제 선택을 기본 스킨으로 덮어쓰지 않는다.

## 10. OTA 적용 시점 차이와 호환성

친구마다 OTA 적용 시점이 다를 수 있으므로 앱에 아직 없는 스킨 ID를 받아도 정상 동작해야 한다.

- 알 수 없는 스킨 ID는 해당 캐릭터의 기본 이미지로 대체한다.
- 대체 표시 때문에 서버 보유·적용 상태를 삭제하거나 초기화하지 않는다.
- 보유 목록에서는 서버의 스킨 이름, 기본 집중 이미지, 업데이트 확인 안내를 표시하고 적용 버튼을 비활성화한다. 기본 이미지를 실제 이벤트 스킨 미리보기로 오인하지 않도록 표시한다.
- OTA 적용 후 해당 스킨을 인식하면 저장된 선택에 따라 표시한다.
- 새 스킨 ID 때문에 프로필·친구 정보 전체 조회가 실패하지 않아야 한다.
- 기능 도입 이전 앱과의 서버 응답 호환성을 확인한다.

## 11. 새 스킨 운영 순서

1. 스킨 ID, 이름, 대상 캐릭터를 정한다.
2. 홈·집중 이미지와 화면별 배치 정보를 준비한다.
3. 앱 에셋과 스킨 연결 목록에 추가한다.
4. 미리보기, 화면 배치, 달성 효과, 미지원 ID 대체 표시를 검증한다.
5. 호환되는 대상 앱에 OTA를 배포하고 정상 수신을 확인한다.
6. 동일한 ID로 서버의 스킨 정의를 등록하고 지급 가능하게 전환한다.
7. 원하는 친구에게 지급하거나 지급과 동시에 적용한다.

## 12. 완료 기준

- 프로필에 별도의 ‘보유 스킨’ 항목이 있고 독립 목록 화면으로 이동한다.
- 스킨 목록의 모든 미리보기가 집중 이미지를 사용한다.
- 관리자 지급 후 친구의 보유 목록에 스킨이 나타난다.
- 지급과 동시에 적용하면 홈·집중 화면의 모습이 변경된다.
- 친구가 보유 목록에서 다른 이벤트 스킨을 선택하거나 스킨 해제로 기본 모습으로 돌아갈 수 있다.
- 보유 이벤트 스킨만 캐릭터별로 묶여 표시되고 기본 스킨 카드와 빈 캐릭터 그룹은 표시되지 않는다.
- 다른 캐릭터의 스킨 선택 시 캐릭터 변경 안내가 표시되고, 적용 후 캐릭터와 스킨이 함께 변경된다.
- 다른 캐릭터 스킨 적용 실패 시 기존 캐릭터와 스킨이 모두 유지된다.
- 다른 친구의 화면에도 적용 상태가 반영된다.
- 중복 지급으로 보유 항목이 늘어나지 않는다.
- 미보유 이벤트 스킨과 권한 없는 관리자 요청을 서버가 거부한다.
- 관리자도 다른 캐릭터의 보유 스킨을 적용하거나 지급하면서 적용할 수 있다.
- 기존 캐릭터 선택 화면에서 다른 캐릭터로 변경하면 기본 스킨으로 돌아가며, 보유 스킨 직접 적용 시에는 선택한 이벤트 스킨을 유지한다. 기존 보유 내역은 두 경우 모두 유지된다.
- 미지원 스킨 ID, 조회 실패, 오프라인에서도 화면 오류 없이 대체 표시한다.
- 앱 재실행 후에도 보유·적용 상태가 유지된다.
- Android와 웹에서 목록 탐색, 적용, 화면별 배치를 확인한다. iOS 대상 배포 시에도 동일하게 확인한다.
- 구현 완료 시 린트와 타입 검사를 통과한다.

- 이미지 서버 저장과 원격 이미지 로딩
- 친구의 직접 이미지 업로드
